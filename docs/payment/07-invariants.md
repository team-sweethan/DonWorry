# P5 불변식과 검증 경계

작성일: 2026-10-20. 기준 코드: `33cb36a`.
상태: **검증 기준 초안. 구현·테스트 실행 없음.**

## 1. 이 문서를 사용하는 방법

불변식은 정상 처리·실패·재시도·동시 요청에서도 깨지면 안 되는 조건이다.
이 문서는 기존 설계를 테스트 가능한 조건으로 정리하며 새 정책을 확정하지 않는다.
출처와 CONFIRMED·PROPOSED·OPEN의 의미는 [README](README.md)를 따른다.

- **독립 검증 가능**: P5에 통제된 입력을 주어 P5 자신의 결과를 검증할 수 있다. 다른 모듈의 실제 동작까지 증명한다는 뜻은 아니다.
- **팀 답변 필요**: 기대 결과나 모듈 간 계약이 미정이므로 조건부 시나리오만 준비한다.
- 독립 검증 가능하더라도 DB 검증에는 스키마·테스트 환경이 필요하다. Q08 승인 전에는 물리 컬럼·제약·마이그레이션을 확정하지 않는다.
- 모든 항목은 아직 미구현·미검증이다. 테스트 대역의 성공을 실제 모듈 연동 성공으로 기록하지 않는다.

S6는 사용자 최초 작업 요청, S1은 저장소 규칙이다. PROPOSED 항목은 기존 문서의 구현 제안이며 이번에 확정으로 바꾸지 않는다.
세부 사례는 [테스트 시나리오](08-test-scenarios.md)의 L 번호를 참고한다.

| INV-P5-11 | 승인 금액·행위자 권한을 클라이언트가 임의로 바꿀 수 없다 | 저장된 주문 금액과 인증된 실행 주체 사용, 변조·무권한 요청에 승인 효과 없음 | S1 및 기존 API 제안. 인증 방식·오류 응답은 Q11·Q15 | L17 |

불변식 07의 금액 비교는 오버플로를 고려해야 한다. 예를 들어 유효한 양수 금액에 대해
`amount ≤ credit_limit - used_amount`를 확인할 수 있다. 금액의 최소 단위·최댓값·반올림 규칙은 여기서 결정하지 않는다.

불변식 09는 업무 효과의 멱등성을 말한다. 모든 HTTP 응답을 바이트 단위로 동일하게 재생한다는 뜻은 아니다.
기존 checkout 설계는 최초 응답에서만 토큰을 제공하고, 완료 요청 재생에서는
`checkoutUrl=null`, `tokenReissueRequired=true`를 반환하는 제안이다. 이 계약은 Q11 합의 대상이다.

## 4. 준비 범위와 다음 단계

지금 할 수 있는 일은 시나리오·입력·관찰값·실패 주입 지점·증거 형식의 문서화다.
P5 내부 테스트의 기대 결과를 먼저 준비하되, 미정인 HTTP 코드·DB 컬럼·타 모듈 상태를 임의로 채우지 않는다.
HELD 자동 취소 시간을 정하거나 질문 6·8의 답을 가정하지 않는다.

다음 단계로 구현 작업을 분해하는 것이 적절하다. 각 작업에 **불변식 ID, 시나리오 ID, 선행 합의 Q번호,
구현 산출물, 검증 방법**을 연결하면 된다. 분해할 때에는 P5 단독 작업과 계약 확정 후 연동 작업을 구분하고,
DB 작업에는 Q08 선행 조건을 둔다. 작업 목록 작성과 실제 구현 착수는 별개로 취급한다.
