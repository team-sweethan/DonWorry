# 0052. P6 최초 잔액 불변과 지출 완료 기록

- 상태: 제안 — 사용자 구현 승인, 팀 리뷰 대상
- 날짜: 2026-10-30
- 관련: #229, #230, #231, ADR-0038·0039

## 결정

시작 잔액·한국 날짜 기준일은 가맹점별 최초 1회만 저장한다. 동일 값 재전달은 허용하고 변경은 거절한다.
최초 설정을 소급하여 과거 완료 정산·지출과 시작 잔액을 중복 집계하지 않도록 서버의 한국 날짜 오늘을 최초 기준일로 사용한다.
DB UNIQUE와 원자적 INSERT ON DUPLICATE KEY no-op 후 현재 행 잠금 조회로 최초 요청 동시성을 처리한다.
최초 설정 메서드는 독립 REQUIRES_NEW·READ_COMMITTED를 사용한다. MariaDB REPEATABLE_READ에서 두 최초 요청의 사전 조회 스냅샷이 동일한 경우 SnapshotIsolationException이 발생한 CI 재현을 반영한다. 전체 앱 격리 수준은 변경하지 않는다. 이 API의 최초 설정은 외부 호출자 트랜잭션과 독립적으로 커밋한다.

지출은 생성 시 예정 상태이며, 사용자의 완료 요청 시 paid_at에 서버 UTC 시각을 저장한다.
지출 행 잠금으로 수정·삭제·완료를 직렬화하고 완료 재전달은 최초 시각을 보존한다.
완료 지출은 변경·삭제하지 않는다. 오류 정정·완료 취소는 후속 계약으로 둔다.
실제 보유 잔액은 후속에서 완료 정산·완료 지출만, 미래 예측은 예정 정산·미완료 지출을 별도로 계산한다.

## 대안

- 잔액 upsert로 덮어쓰기: 기준일과 누적 거래가 어긋나 과거 금액을 중복 집계할 수 있다.
- 예정일 경과 시 자동 지출: 실제로 출금하지 않은 금액을 보유 잔액에서 차감한다.
- 별도 완료 테이블: 일회성 지출당 완료 1회 범위에서는 nullable paid_at과 행 잠금으로 표현한다. 정기 지출은 후속 발생 건별 식별 계약을 사용한다.
- 완료 시각을 요청에서 받기: 미래/과거 조작과 날짜 기준 혼동을 막기 위해 우선 서버 현재 시각으로 한정한다.

## 영향

P6 신규 테이블 2개·DTO·일회성 관리 API와 테스트. P1/P5 코드·공유 migration·프론트 변경 없음.
기존 로컬 upsert API와 다른 확정 동작이며 공개된 dev API를 변경하는 것은 아니다.
상세 컬럼과 API·미구현 범위는 [설계/ERD](../settlement/balance-expenses-api.md)를 따른다.
