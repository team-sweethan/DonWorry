# 0054. 전액 취소·환불과 정산 완료 후 취소 허용

- **상태:** 정책 결정 — 2026-10-31 사용자 확인, 상세 연동 계약은 담당 간 후속 합의
- **날짜:** 2026-10-31
- **관련:** [Issue #153](https://github.com/team-sweethan/DonWorry/issues/153), [Issue #233](https://github.com/team-sweethan/DonWorry/issues/233), [ADR-0012](0012-payment-settlement-dependency.md)
- **영향 받는 담당:** P5 결제, P6 정산, P1/CakeShop. HELD·Case·직원 판정에 영향이 있으면 P3와 확인한다.

## 배경

ADR-0012는 정산 완료 이후 취소할 수 없다는 전제로 payment → settlement 의존 방향을 정했다. 2026-10-31 사용자가 정산 완료 여부와 관계없이 취소 가능하며 전액 취소만 지원한다고 결정했다. 이 ADR은 해당 취소 제한 전제만 대체한다. 기존 ADR 본문은 당시 결정의 기록으로 보존한다.

## 결정

- 최초 지원 범위는 전액 취소·전액 환불이다. 부분 취소·부분 환불은 지원하지 않는다.
- 매입 전은 승인 취소, 매입 후는 전액 환불로 구분한다. P5가 취소·환불 처리를 담당하고 P6는 전달받은 결과의 정산 반영을 담당한다.
- 정산 완료 여부만으로 취소·환불을 거절하지 않는다. 이는 모든 결제 상태에서 무조건 성공한다는 의미가 아니다. PENDING·HELD·CAPTURED 등 상태별 요청 조건과 매입 진행 중 처리는 #153에서 정한다.
- payment → settlement 의존 방향과 ADR-0012의 공개 api·이벤트 타입 배치 규칙은 유지한다. 이 정책으로 allowedDependencies를 변경하지 않는다.
- 취소 시작 통지와 취소 진행 중 정산 보류는 이번 범위의 필수 절차로 두지 않는다. P5는 성공이 확정된 취소 결과를 P6에 전달한다. 실패 시 정산 금액을 변경하지 않으며, 결과 미확정은 P5가 추적·복구하고 성공 확인 후 전달한다.
- P6는 결과 반영 시 정산 전이면 해당 결제를 지급 대상에서 제외한다. 정산 완료 후이면 기존 정산 기록을 보존하고 별도 차감 내역을 기록하여 같은 가맹점의 다음 정산에서 차감한다. 차감액이 다음 정산금을 초과하면 남은 차감액을 이후 정산으로 이월한다.
- 다음 정산이 없으면 미회수 금액으로 남긴다. 별도 회수 방법·기한은 후속 결정이며 자동 출금 등을 가정하지 않는다.
- 고객 환불액은 결제 전액이다. 가맹점 정산 차감액은 수수료 반환 정책에 따라 달라질 수 있으므로 고객 환불액과 같다고 가정하지 않는다. 수수료 반환 및 차감액 계산식은 P6와 후속 확정한다.
- 취소 결과 중복 수신은 한 번만 반영한다. P6는 취소 반영과 정산 배치의 동시 실행을 제어하여 지급 제외 또는 정산 후 차감 중 하나만 적용되게 해야 한다. P5 성공 기록 후 전달 실패·P6 저장 실패는 재전달로 복구할 수 있어야 한다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 정산 완료 후 취소 금지 유지 | 정산 완료 여부와 관계없이 취소를 허용한다는 사용자 정책과 맞지 않는다 |
| 최초 범위에 부분 취소·부분 환불 포함 | 사용자가 전액 취소만 지원하기로 결정했다 |
| 정책 변경과 함께 모듈 의존 방향 반전 | P5가 P6 공개 조회를 사용하는 기존 구조를 바꿀 필요가 없으며 기존 이벤트 계약에 불필요한 영향을 준다 |
| 취소 시작 통지로 정산을 보류하고 실패 시 해제 | 정산 후 취소를 허용하므로 필수로 두지 않는다. 보류 해제·미확정 보류 기간의 복잡성을 줄이고 성공 결과와 후속 차감으로 처리한다 |
| 이미 완료된 정산 기록을 취소 상태로 덮어쓰기 | 기존 지급 사실이 사라지므로 별도 차감 내역을 남긴다 |

## 후속 합의

- #153: 요청 권한·식별자·멱등성, 취소 금액 검증, 성공·실패·미확정 결과와 조회, 매입·직원 조치와의 경합, 전달 필드·시점·재전달을 정한다.
- #233: 성공 결과 수신·지급 제외·차감 및 이월을 구체화한다. 수수료 반환 정책·차감액 계산식·미회수 금액의 별도 회수 기준·정산 배치와의 잠금 및 멱등성·저장 구조는 P6와 후속 합의한다. P6 담당자의 구현 계약 확인까지 완료된 것으로 간주하지 않는다.
- #189의 CaptureReader는 관측한 매입 사실을 제공한다. 빈 결과만으로 매입 전을 확정하거나 조회만으로 매입·취소 경합이 해결된다고 가정하지 않는다.

## 영향

- API: 이번 변경은 정책 기록이다. 취소·환불 HTTP API와 P5/P6 전달 계약은 #153 후속이며 기존 API 동작은 바꾸지 않는다.
- DB: 이번 변경에 스키마·데이터 변경은 없다. 필요한 저장 구조는 소유 담당·ERD 합의 후 별도 구현한다.
- 화면: 구현 변경은 없다. CakeShop 주문·재고·쿠폰 반영은 후속 계약 대상이다.
- 테스트: 후속 구현에서 매입 전·후와 정산 완료 후 전액 취소, 부분 요청 거절, 중복·동시 요청·응답 유실·실패 복구, 정산 배치 경합 시 단일 반영, 차감액 부족 이월·미회수 잔액 보존을 검증한다.
- 문서: #153과 ADR 목록에 정책을 반영하고 ADR-0012 상태에 부분 대체를 표시한다. #233 상세 계약 및 Notion 정책 대조·동기화는 후속이다.

## 검증

문서 변경 검사는 `python3 .github/scripts/check_md_links.py`와 `git diff --check`로 수행하며 실행 결과는 작업 보고에 기록한다. 취소·환불 API, P6 정산 반영 및 통합 동작은 이번에 구현하거나 검증하지 않는다.
