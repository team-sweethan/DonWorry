# 0049. P6 정산 완료의 일일 배치와 건별 트랜잭션

- 상태: 제안 — 사용자 구현·PR 승인, 팀 리뷰 대상
- 날짜: 2026-10-30
- 관련: #234, #233, [픽업 수신 ADR](0043-p6-pickup-receiving.md)

## 결정

실제 픽업 후 72시간이 지난 정산 예정 건을 한국 시간 매일 03시에 처리한다.
기본 자동 실행은 비활성으로 보존하며 별도 환경 설정으로 활성화한다.
실제 처리 시각을 완료일 기준으로 사용하고 기존 금액·수수료·가능 시각을 보존한다.

후보 ID 상한과 기준 시각을 고정하고 keyset으로 조회한다. 조회 연결을 반환한 후 각 정산을 독립 트랜잭션으로 완료한다.
픽업 처리와 같은 주문 → 정산 잠금 순서를 사용하며 잠금 후 업무 조건을 재검사한다.
동시 실행은 같은 행의 상태 재확인으로 중복 완료를 방지한다. 분산 스케줄러의 전체 실행 횟수 자체를 1회로 제한하지는 않는다.

## 대안

- 전체 건을 한 트랜잭션으로 처리: 한 건 실패로 기존 성공 건도 롤백되고 잠금·연결 유지가 길어진다.
- OFFSET 조회: 완료되어 목록에서 빠진 행 때문에 다음 후보를 건너뛸 수 있다.
- 픽업 수신 즉시 완료: 72시간 경과 후 처리와 일일 일정 요구를 충족하지 못한다.
- 가능 시각을 완료 시각으로 저장: 실제 완료되지 않은 시간을 지급일처럼 표시한다.

## 영향

P6 Entity·Repository·배치 서비스와 테스트만 추가·수정한다. 새 DB 컬럼·migration·외부 API는 필요 없다.
취소와의 경합은 이번 범위 밖이며 운영 활성화 전에 후속 계약을 적용해야 한다.
현금흐름의 다음 배치 기준 예측은 별도 후속이다. 자세한 동작은 [배치 문서](../settlement/completion-batch.md)를 따른다.
