# 0047. 신청 메일 수동 복구와 보관 기한 정리

- **상태:** 제안 — #315 PR 4 사용자 구현 승인·구현 반영, PR 리뷰 대상
- **날짜:** 2026-10-29
- **관련:** #315, ADR-0043·0044·0045, ADR-0046(신청 승인·첫 설정)
- **영향 받는 담당:** P1. 다른 담당 API·금융/조사 테이블·모듈 의존 변경 없음.

## 배경

PR 2·3은 발송과 신청/발급 결과를 분리하지만 관리자 복구, 개인정보 자동 삭제, 공개 화면의 서버 설정 반영은 남아 있다.
passwordChangeRequired는 첫 설정과 관리자 초기화가 공유하므로 플래그만 보고 첫 설정 링크를 재발급하면 초기화로 폐기한 기능을 다시 열 수 있다.

## 결정

재발송은 최신 발송 ID를 확인한 새 시도로 저장하고 커밋·잠금 해제 후 SMTP를 호출한다. 승인 계정은 재생성하지 않는다. 첫 설정 토큰 이력과 현재 계정/가맹점 상태를 검사해 초기화·첫 설정 완료 뒤 재발급을 막는다.
최신 발송·토큰은 시각 대신 deliveryId/tokenId로 결정한다. 같은 신청의 발급은 신청 PK 잠금으로 직렬화하며 서버 시각 역행이 발급 순서를 바꾸지 않게 한다.
오래된 PENDING은 조회에서 UNKNOWN으로 해석한다. 미확인 7일·반려 30일은 신청 PK 잠금 후 재검사하고 발송 → 토큰 → 신청을 원자 삭제한다. 기능 off에서도 보관 기한 정리는 수행한다.
공개 화면은 기존 서버 enabled 설정을 조회하며 설정 확인 전에는 신청 진입을 허용하지 않는다.
상세 API·횟수·잠금·삭제 간격·검증 계획은 [PR 4 설계](../identity/315-recovery-design.md)를 따른다. 새 정책의 제안이며 기존 합의나 검증 결과로 간주하지 않는다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 원문 토큰을 저장해 자동 재전송 | 해시 저장 계약을 바꾸며 UNKNOWN의 중복 전달도 해결하지 못한다 |
| 승인 요청 재수행 | 계정 발급과 메일 복구를 혼동한다 |
| passwordChangeRequired만 검사 | 관리자 초기화 뒤 첫 설정 재발급을 허용할 수 있다 |
| 과거 발송 행 재사용 | 시도별 결과와 지연 콜백의 구분을 잃는다 |
| 조회에서 PENDING을 DB UNKNOWN으로 변경 | 읽기 부작용과 결과 저장 경쟁이 생긴다 |
| 익명화/soft delete | 합의한 삭제·예약 해제와 다른 저장 정책이다 |
| 자식·신청을 다른 커밋으로 삭제 | 실패 시 부분 삭제가 남는다 |
| 프론트 빌드 플래그 | 서버 기능 설정과 배포에 따라 달라질 수 있다 |

## 영향

- API: 관리자 메일 요약/이력·재발송, 공개 설정 조회, 새 CSRF 보호.
- DB: 기존 구조 사용. 신청·토큰·발송 삭제 동작 구현. 승인·금융/조사 기록 보존.
- 화면: 복구 영역, 공개 신청 가드, 비활성/오류 안내.
- 테스트: MariaDB 원자성·시간 경계·경쟁, 프론트 계약, Mailpit/브라우저 전체 흐름.
- 문서: identity 설계·README 실행 근거/운영 절차. Gmail·배포·백업 보관·승인 신청 이용 종료 기준은 별도 확인.

## 검증

PR4를 구현했으며 최종 실행 근거는 identity README의 PR4 기록을 따른다. 브라우저·Gmail 실제 수신·운영 배포는 미검증이다. 아래 설계 재검토/기존 회귀 기록은 변경 전 근거로 보존한다.
2026-10-29 기준 코드 `897b572` 대조 재검토에서 기본 목록 필터 충돌, 시각 기반 최신 판단, 기존 입력 오류/재발송 제한 응답의 연결 누락을 찾아 상세 설계에 보완했다. 실행 검증 결과는 아니다.
브라우저를 제외한 2차 재검토에서는 결과 저장/삭제 경합을 PENDING 조건부 UPDATE로 구체화하고, 제한 정보의 상세 재조회·기존 CSRF 재전송·조회 스냅샷·삭제 후보/커서/UTC 계약과 자동 검증 기준을 보완했다. 기존 회귀 검사와 PR4 신규 동작 검증은 상세 설계에서 구분한다.
동일 HEAD `897b572`의 기존 코드 회귀 검사에서 backend check/mariaDbTest와 frontend lint/format:check/build/test가 통과했다. 상세 수치·경고·미검증은 [실행 기록](../identity/315-recovery-design.md#이번에-실행한-회귀-검사)을 따른다.
