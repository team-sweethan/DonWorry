# 0004. 미승인 결제 만료 상태 분리

- **상태:** PROPOSED — 사용자 선택(질문 2-B), 팀 합의 대기, 구현 없음
- **날짜:** 2026-10-20
- **관련:** [선택 기록](../payment/README.md), [미결 목록](../payment/12-open-questions.md)
- **영향 받는 담당:** P5·CakeShop·P1

## 배경

REQUESTED가 기한이 지나도 활성 주문번호를 점유하며 종료 경로가 없었다.

## 결정 제안

미승인 만료를 별도 상태로 분리한다. 이름은 EXPIRED 제안이며 REQUESTED에서만 전이한다. 카드 원장·한도·canceled_at 변경 없이 이력과 활성 키 해제를 저장한다. HELD 자동 만료와 고객 자발적 중단은 포함하지 않는다.

사용자가 방향을 선택했으나 팀 채택·Notion 정본 동기화는 확인하지 않았다. 세부 계약(상태명·기한 경계·만료 실행 방식·주문 연장/재결제)은 팀 합의 대기다. 기존 ADR을 수정·대체하지 않는다.

## 고려한 대안

| 대안 | 선택하지 않은 이유·영향 |
|---|---|
| CANCELED로 통합 | 승인 후 취소와 의미가 섞이므로 선택하지 않았다. 별도 상태는 API·화면·CHECK 변경 비용이 있다. |

## 영향

- API·DB·화면·운영: 상태 API·화면·payment 상태 제약·기한 인덱스.
- 테스트: 만료/승인 경합, EXPIRED 카드 작업 없음, 활성 주문 키 해제.
- 문서: 팀 합의 후 정본과 관련 명세를 함께 동기화한다. 이번에는 Markdown만 수정한다.
- 질문 6(P6 정산 구조)과 질문 8(케이스 생성 기준)은 OPEN으로 유지하며 이 결정으로 확정하지 않는다.

## 검증

미검증 — 구현·DB·트랜잭션 테스트는 수행하지 않았다. 문서 문법 검사는 [P5 안내](../payment/README.md)의 후속 수정 검증 기록을 따른다.
