# 0043. P6 주문·픽업 수신과 상품 스냅샷의 원자적 저장

- 날짜: 2026-10-29
- 상태: 사용자 승인, PR 리뷰 대상
- 관련: #226, #227, #333, 채택된 ADR-0037(HMAC)·0038(identity 의존)

## 결정

픽업 예정·실제 시각과 주문 상품 스냅샷을 P6 주문 테이블과 자식 테이블에 저장한다.
같은 order_id 행을 DB 잠금 기준으로 사용해 매입/픽업의 도착 순서와 동시 재전달을 처리한다.
매입 완료·정산 예정금 생성은 기존 단일 트랜잭션을 유지하고, 픽업 트랜잭션이 기존 정산 일정을 연결한다.
상품명·수량·배열 순서를 보존한다. 같은 목록은 재사용하고 다른 목록은 409로 거절한다.
P1 CurrentMerchant 공개 계약만 사용하며 공통 인증·다른 모듈 저장소·P5 이벤트 계약은 변경하지 않는다.

## 대안과 이유

- JVM 잠금: 여러 앱 인스턴스 사이에서 같은 주문을 보호하지 못한다.
- 상대 기록 조회만 사용: 동시 최초 처리에서 두 트랜잭션이 서로의 기록을 못 보고 연결을 놓칠 수 있다.
- merchant_id NOT NULL만 허용: 기존 내부 매입 선도착의 주문 확보 행을 표현하지 못한다.
- UNIQUE(merchant_id, order_id)만 사용: NULL 가맹점 행의 중복을 막지 못한다. 현 단일 연동은 order_id UNIQUE를 유지하고 확대는 별도 전환한다.
- 부모 상품명/수량 한 쌍: 여러 상품 주문을 표현하지 못한다.
- 상품명 UNIQUE 또는 임의 합치기: 같은 이름의 다른 옵션 항목을 잃는다.
- CakeShop 상품 FK: 다른 서버 DB에 의존하고 주문 당시 이름을 재현하지 못한다.
- 공유 자금관리 접근 서비스 전체 포함: 이번 범위와 무관한 사장님 세션·조회 코드까지 들어가므로 픽업 전용 서비스/Advice로 분리한다.

## 영향과 미검증

P6 SQL 3개·Entity·Repository·Controller·Service·테스트와 P6 문서만 추가/변경한다.
Settlement에는 일정/예약 시각만 추가하며 배치 완료 로직·취소·현금흐름·프론트는 포함하지 않는다.
다른 모듈의 Java 공개 계약, allowedDependencies, 공용 보안 설정은 채택된 상태 그대로다.
상세 API와 테이블은 docs/settlement/README.md에서 확인한다.
실제 CakeShop 전송·운영 키·도메인·Notion 동기화는 로컬 검증과 구분한다.
