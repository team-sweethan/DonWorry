# 0007. P3 결정과 P5 실행의 공동 커밋

- **상태:** PROPOSED — 사용자 선택(질문 5-A), 팀 합의 대기, 구현 없음
- **날짜:** 2026-10-20
- **관련:** [선택 기록](../payment/README.md), [미결 목록](../payment/12-open-questions.md)
- **영향 받는 담당:** P3·P5·P6

## 배경

P3 결정만 저장되고 P5 실행은 실패하는 상태의 처리 책임이 미정이었다.

## 결정 제안

P3 결정 저장과 P5 유지/취소 실행을 같은 트랜잭션으로 커밋한다. P3 REQUIRED·P5 MANDATORY를 제안하며 어느 쪽 실패든 결정·상태·원장·응답을 롤백한다. 직원 성공 응답은 공동 커밋 뒤에 보낸다.

사용자가 방향을 선택했으나 팀 채택·Notion 정본 동기화는 확인하지 않았다. 세부 계약(P3 결정 키·롤백 후 동일 ID 전달·중복 결정 제약·잠금 순서)은 팀 합의 대기다. 기존 ADR을 수정·대체하지 않는다.

## 고려한 대안

| 대안 | 선택하지 않은 이유·영향 |
|---|---|
| P3 선커밋 후 실행 재시도 | 실행 대기/실패 상태가 추가되므로 선택하지 않았다. 공동 커밋은 실패한 결정 자체도 롤백되며 긴 잠금 범위에 주의해야 한다. |

## 영향

- API·DB·화면·운영: P3 API·결정 저장·P5 ReviewExecutor·P6 취소 참여.
- 테스트: P3 저장 실패 시 P5 롤백, P5 실패 시 결정 롤백, 결정 재전송 1회 실행.
- 문서: 팀 합의 후 정본과 관련 명세를 함께 동기화한다. 이번에는 Markdown만 수정한다.
- 질문 6(P6 정산 구조)과 질문 8(케이스 생성 기준)은 OPEN으로 유지하며 이 결정으로 확정하지 않는다.

## 검증

미검증 — 구현·DB·트랜잭션 테스트는 수행하지 않았다. 문서 문법 검사는 [P5 안내](../payment/README.md)의 후속 수정 검증 기록을 따른다.
