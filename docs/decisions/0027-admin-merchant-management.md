# 0027. 관리자 가맹점 관리와 정지·로그인 순서 보장

- **상태:** 제안 — #130 사용자 구현 승인, PR 리뷰 대상
- **날짜:** 2026-10-25
- **관련:** #68, #124, #125, #128, #129, #130, ADR-0020·0022·0024·0025
- **영향 받는 담당:** P1 주환. P6 수수료율 공유 예정, 정산 적용·공개 조회 확장은 별도 합의 대상.

## 결정

- [#130 설계](../identity/130-admin-merchant-design.md)의 관리자 HTTP·오류·입력·화면 계약을 제공한다. 기존 /api/admin/** 관리자 제한과 CSRF 클라이언트를 재사용하며 서버 CSRF 기본값 false는 유지한다.
- 가맹점 코드·이름·수수료율을 받아 ACTIVE로 생성하고 상태만 변경한다. 삭제·코드 수정·수수료율 수정·웹훅 편집은 제공하지 않는다.
- 기존 merchants·admin_change_histories를 재사용한다. 이력과 업무 변경은 같은 트랜잭션에 기록하며 세션 종료는 실제 커밋 뒤 수행한다.
- 가맹점 상태와 계정 상태를 분리한다. 재활성화는 별도 DISABLED 계정이나 만료 세션을 복구하지 않는다. 정지 가맹점 로그인은 기존 AUTH_004·동일 문구로 실패한다.
- 단일 서버 메모리 세션에 맞춰 가맹점별 고정 분할 잠금을 추가한다. 로그인·가맹점 상태 변경·사장님 계정 생성이 공유하며 가맹점 → 계정 → 짧은 세션 모니터 순서로 획득한다.
- 로그인은 가맹점 상태 확인에서 세션 등록까지, 정지는 DB 커밋에서 모든 소속 세션 종료까지 잠금을 유지한다. 최초 조회 후 새로 생성된 계정도 가맹점 잠금 없이 로그인하지 못하게 확인한다.
- 수수료율은 BigDecimal로 `0 이상 1 미만`, 소수 6자리까지 검사한다. 화면 기본값 1%는 비율 0.010000이며 % 입력에서 소수 비율로 반올림 없이 변환한다.
- TenantReader·TenantSummary·모듈 의존과 P6 정산 계산은 변경하지 않는다. 다중 서버와 전체 업무 인가는 후속 범위다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 정지 커밋 후 세션만 종료 | 이미 인증한 로그인이 종료 후 새 세션을 등록할 수 있다 |
| 정지 시 기존 소속 계정 잠금만 획득 | 동시에 새 계정이 생성되면 대상 목록 밖에서 로그인이 가능하다 |
| 계정 잠금을 잡은 뒤 가맹점 잠금 획득 | 정지·생성과 역순 경로가 생겨 교착할 수 있다 |
| 전체 로그인·정지를 전역 모니터에 직렬화 | 무관한 가맹점의 BCrypt·DB 작업까지 막는다 |
| 가맹점 정지 시 계정도 일괄 DISABLED | 재활성화 시 원래 별도 정지된 계정과 구별할 수 없다 |
| 이력 비동기 저장·세션 종료 후 커밋 | 이력이 없거나 DB 실패인데 세션만 종료될 수 있다 |
| 수수료율을 double로 반올림해서 저장 | 자릿수 초과를 조용히 허용하거나 경계값을 바꾼다 |
| 공개 조회에 수수료율을 함께 추가 | ADR-0020 및 ADR-0012의 P6 합의 범위를 넘는다 |

## 영향과 검증

- API: 관리자 가맹점 목록·상세·생성·상태와 ADMIN_007~009 추가. OPERATOR 로그인에 가맹점 검증을 추가한다.
- DB: 스키마 변경 없이 기존 가맹점·이력 행 INSERT/UPDATE. 이력 실패는 함께 롤백한다.
- 화면: 관리자 가맹점 메뉴·세 화면·계정 생성 링크. 기존 공통 API·세션 만료 처리를 사용한다. 입력한 수수료율은 아직 정산에 반영되지 않음(현재 1% 고정)을 생성·목록·상세에 표시한다.
- 한계: 로그인은 가맹점 상태 확인과 세션 등록 사이를 막기 위해 BCrypt 검증 동안에도 가맹점 잠금을 유지한다. 같은 가맹점의 사장님 로그인과 잠금 칸(가맹점 ID mod 256)이 같은 가맹점의 로그인은 직렬화되며, 한 계정에 대한 반복 로그인 시도가 이들의 로그인을 늦출 수 있다. 계정 잠금 뒤 가맹점 잠금을 얻도록 바꾸면 정지 경로와 역순이 되어 교착할 수 있어 받아들인다. 다중 서버·분산 잠금 전환 때 다시 검토한다.
- 테스트: 권한·입력·중복·비율 정밀도·세션 종료·상태 복구·원자성·순서 보장·기존 계정 변경 회귀와 프론트 계약을 검사한다.
- 실제 실행 결과와 미검증은 [identity README](../identity/README.md)에 기록한다. 이 ADR 자체는 검사 통과를 의미하지 않는다.
