# 0045. 공개 신청·이메일 확인 HTTP와 CSRF

- **상태:** 제안 — P1 사용자 설계·구현 승인, PR 리뷰 대상
- **날짜:** 2026-10-29
- **관련:** #315 PR 2, #323(PR 1), ADR-0024·0025·0028
- **영향 받는 담당:** P1. 다른 모듈 공개 Java API·허용 의존·금융 테이블 변경 없음.

## 결정

로그인 없는 세 POST를 정확한 경로로 열고 CSRF는 전역 설정과 무관하게 검사한다. 확인은 명시적 POST로만 수행하고 URL fragment 토큰을 본문으로 보낸다. 사업자 자격·승인과 이메일 확인을 분리한다.

상세 스키마·오류·유효기간·트랜잭션·후속 경계는 [설계](../identity/315-application-design.md)를 따른다.
P1 담당자의 이번 진행 승인으로 저장소 ERD·ADR에 먼저 기록한다. Notion 최신 대조·동기화는 미수행이다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| GET 링크로 확인 | 메일 미리보기/보안 스캐너가 일회용 링크를 소비한다 |
| 공개 API CSRF 예외 | 타 사이트 폼 제출로 메일을 보내는 요청을 허용한다 |
| 전역 CSRF 활성화 | 다른 담당 API 계약까지 바꾼다 |

## 영향과 검증

- DB: P1 신청·토큰·메일·요청 제한 테이블과 nullable 사업자번호. 기존 migration 보존.
- API·화면: 공개 신청·확인·재발송, 랜딩·로그인 진입 연결. 계정 발급은 PR 3.
- 테스트: 실제 MariaDB 제약·동시 처리·보안·토큰·SMTP 실패·프론트 계약.
- 실행 결과·미검증은 identity README와 PR에 기록한다. 설계 자체는 검증 완료를 뜻하지 않는다.
