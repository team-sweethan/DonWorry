# 0005. checkout 토큰 재발급

- **상태:** PROPOSED — 사용자 선택(질문 3-A), 팀 합의 대기, 구현 없음
- **날짜:** 2026-10-20
- **관련:** [선택 기록](../payment/README.md), [미결 목록](../payment/12-open-questions.md)
- **영향 받는 담당:** P5·CakeShop·P1

## 배경

해시만 저장하면 유실된 최초 진입 토큰을 재생할 수 없다.

## 결정 제안

인증된 CakeShop 서버가 재발급 API로 새 토큰을 받는다. 같은 payment의 해시를 교체하여 이전 토큰을 무효화한다. 원문을 저장하지 않으며 동일 키에는 안정적인 접수 결과만 재생한다. 원문 진입 정보는 최초 성공 응답에서만 제공한다.

사용자가 방향을 선택했으나 팀 채택·Notion 정본 동기화는 확인하지 않았다. 세부 계약(URL·헤더·토큰 수명·동시 재발급·재생 예외 DTO)은 팀 합의 대기다. 기존 ADR을 수정·대체하지 않는다.

## 고려한 대안

| 대안 | 선택하지 않은 이유·영향 |
|---|---|
| 원응답 암호화 저장 | 키·보존 관리가 추가되므로 선택하지 않았다. 재발급은 기존 결제창 무효화·응답 역전 처리가 필요하다. |

## 영향

- API·DB·화면·운영: CakeShop API·결제창·payment 해시·멱등 결과.
- 테스트: 동일 키 추가 회전 없음, 이전 토큰 거부, 응답 유실 복구.
- 문서: 팀 합의 후 정본과 관련 명세를 함께 동기화한다. 이번에는 Markdown만 수정한다.
- 질문 6(P6 정산 구조)과 질문 8(케이스 생성 기준)은 OPEN으로 유지하며 이 결정으로 확정하지 않는다.

## 검증

미검증 — 구현·DB·트랜잭션 테스트는 수행하지 않았다. 문서 문법 검사는 [P5 안내](../payment/README.md)의 후속 수정 검증 기록을 따른다.
