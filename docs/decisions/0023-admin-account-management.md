# 0023. 관리자 계정 관리와 강제 비밀번호 변경

- **상태:** 제안 — 사용자 구현 승인, PR 리뷰 대상
- **날짜:** 2026-10-25
- **관련:** #68, #124, #125, #128, #129, #130, ADR-0022
- **영향 받는 담당:** P1 주환. 다른 담당 테이블·모듈 공개 Java 계약 변경 없음.

## 결정

- 계정 관리 HTTP는 `/api/admin/**`로 두고 SecurityConfig에서 SessionUser.role=ADMIN을 검사한다. 현재 인증 객체의 authorities는 비어 있으므로 hasRole만 사용하지 않는다.
- 생성 역할은 OPERATOR·SECURITY_STAFF뿐이다. 기능 권한은 OPERATOR에만 설정한다. ADMIN 권한은 기존 역할 계산을 유지한다. 계정 삭제·역할/가맹점 변경은 제공하지 않는다.
- 상세 HTTP·DB 계약은 [#129 설계](../identity/129-admin-account-design.md)를 따른다. 로그인·me 응답에 passwordChangeRequired를 추가한다.
- 강제 변경 계정의 인증 경로 외 `/api/**` 요청은 403 AUTH_008로 거절한다. 익명 업무 요청과 `/internal/**` 정책은 기존대로 둔다. 이 계정 상태 제한만 #129에 포함하며 전체 역할·가맹점별 인가와 CSRF는 #68 5단계다.
- 임시 비밀번호는 SecureRandom으로 생성하고 기존 PasswordPolicy와 BCrypt를 재사용한다. 생성·초기화 응답에서만 원문을 한 번 전달하며 no-store를 설정한다. 원문·해시는 이력·로그·세션에 넣지 않는다.
- 생성·권한·상태·초기화는 같은 트랜잭션에 INSERT 전용 이력을 기록한다. 같은 상태·권한 재요청은 실제 변경·이력·세션 종료를 반복하지 않는다.
- 계정 변경은 ADR-0022의 실제 loginId 잠금 안에서 DB 재조회·변경·커밋·expireAll까지 수행한다. 잠금 대기 뒤 수행자의 세션도 재확인한다. 수행자·대상 잠금은 고정 분할 인덱스 순서로 획득해상호 정지 등에서 교착을 방지한다.
- 본인 비밀번호 변경은 플래그를 해제하고 현재 인증 컨텍스트를 명시 저장한다. 재로그인 전략은 실행하지 않아 현재 세션 ID를 유지한다. 프론트는 성공 후 me를 갱신한다.
- 비밀번호 정책은 #128의 PasswordPolicy를 그대로 사용한다. 단, 강제 변경 중(DB `password_change_required=true`)에는 새 비밀번호가 현재 임시 비밀번호와 같으면 400 AUTH_009로 거절한다. 관리자가 아는 비밀번호를 계속 쓰면 강제 변경의 목적이 사라지기 때문이다. 일반 본인 변경의 동일 비밀번호 허용은 #128 그대로다.
- 사용자가 2026-10-25에 이번 P1 DB 변경에 대해 Notion 선행 반영을 저장소 ERD·ADR 기록으로 대체하도록 승인했다. Notion 최신 ERD 확인·동기화는 미수행이다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 화면에서만 강제 변경 | API 직접 호출로 업무 사용을 우회할 수 있다 |
| DB 커밋 뒤 세션 종료만 호출 | 옛 상태로 인증을 끝낸 로그인이 종료 뒤 등록될 수 있다 |
| 변경 이력을 커밋 뒤 비동기 저장 | 계정만 바뀌고 이력이 없는 상태가 생긴다 |
| 강제 변경에서도 임시 비밀번호 재사용 허용 | 관리자가 아는 비밀번호가 그대로 남아 강제 변경을 우회할 수 있다 |
| 모든 본인 변경에서 동일 비밀번호 금지 | #128 합의 정책을 바꾸는 일이라 이번 범위를 넘는다 |
| 비밀번호 원문을 저장해 다시 조회 | 일회 제공 계약을 어기고 유출 범위를 늘린다 |
| 역할·가맹점 수정까지 제공 | #129 범위를 넘으며 기존 업무 기록 의미에 영향을 준다 |
| 전체 서버 인가·CSRF를 함께 활성화 | 다른 담당의 기존 API 계약과 #68 단계별 적용을 변경한다 |

## 영향과 검증

- DB: P1 컬럼·CHECK와 P1 관리 이력 테이블. 새 migration 세 개로 추가한다.
- API·화면: 관리자 목록·생성·상세, ACTIVE 가맹점 선택, 강제 변경과 me 갱신.
- 테스트: 관리자 401·403, 생성 정책, 상태·권한·초기화와 이력 원자성, 로그인 경쟁 조건, 실제 MariaDB 제약, 프론트 경로·API·인증 갱신.
- 실행 결과·미검증은 identity README에 기록한다. 작성 시점에는 구현과 검증이 진행 중이다.
