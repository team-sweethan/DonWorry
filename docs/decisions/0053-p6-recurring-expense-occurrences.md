# 0053. P6 정기 지출 규칙과 회차별 완료 기록

- 상태: 제안 — P6 사용자 구현 승인, 팀 리뷰 대상
- 날짜: 2026-10-30
- 관련: #231, ADR-0052

## 결정

정기 지출은 매일·매주·매달 규칙을 저장하고 미래 발생 내역은 기간 조회 시 계산한다.
실제 지출 완료 시에만 별도 회차 기록을 저장한다. 규칙 ID와 원래 예정일의 UNIQUE로 한 회차를 식별한다.
완료는 서버 UTC 시각을 사용하고 한국 날짜로 실제 지출일을 산출한다. 미래 회차를 미리 지출해도 원래 예정일은 보존한다.
완료 기록에는 금액·제목·분류·메모를 복사한다. 규칙 중단 후에도 실제 지출 기록은 유지한다.
중단과 완료는 동일 규칙 행의 쓰기 잠금으로 직렬화한다. 완료 재전달은 기존 ID·금액·시각을 반환한다.

## 대안

- 미래 회차를 미리 전부 INSERT: 무기한 규칙의 종료 범위가 없고 중단 시 삭제·재생성 동기화가 필요하다.
- 규칙에 paid_at 하나만 저장: 매주·매달 다른 회차의 완료를 구분할 수 없다.
- 규칙 물리 삭제: 과거 지출 이력과 회차 식별자가 사라진다. 중단일을 기록한다.
- 일회성 지출 테이블에 회차도 생성: 예정 회차 계산과 일회성 API 간 수정·중복 계약을 확장해야 하므로 이번 범위에서는 별도 P6 완료 기록으로 둔다.

## 영향

P6 신규 migration 1개, 테이블 2개, 정기 지출 API와 검증. P1·P5·공용 설정·기존 migration·프론트 변경 없음.
실제 보유 잔액·현금흐름 예측 통합은 5단계에서, 프론트 실제 API 연결은 6단계에서 진행한다.
컬럼·응답 의미·조회 제한은 [정기 지출 API/ERD](../settlement/recurring-expenses-api.md)를 따른다.
