# 0006. FDS 실제 시도 기록의 독립 저장

- **상태:** PROPOSED — 사용자 선택(질문 4-A), 팀 합의 대기, 구현 없음
- **날짜:** 2026-10-20
- **관련:** [선택 기록](../payment/README.md), [미결 목록](../payment/12-open-questions.md)
- **영향 받는 담당:** P2·P5

## 배경

P5 승인 실패와 평가 기록을 함께 롤백하면 실제 실패 시도가 집계에서 사라진다.

## 결정 제안

실제 평가 시도를 집계하고 P2 기록을 P5 롤백과 분리한다. 동일 논리 시도의 기술 재전송은 추가 집계하지 않는다. P2가 P5 잠금을 기다리는 역호출을 금지하는 경계를 제안한다.

사용자가 방향을 선택했으나 팀 채택·Notion 정본 동기화는 확인하지 않았다. 세부 계약(시도 접수 내구성·evaluationId·원입력 저장·카드 변경·재평가 기간·REQUIRES_NEW 구현)은 팀 합의 대기다. 기존 ADR을 수정·대체하지 않는다.

## 고려한 대안

| 대안 | 선택하지 않은 이유·영향 |
|---|---|
| P5와 공동 롤백 | 구현은 단순하지만 장애 중 시도 집계가 누락된다. 독립 저장은 시도 접수·실패 보존·입력 고정·재시도 계약이 필요하다. |

## 영향

- API·DB·화면·운영: P2 저장·FDS API·P5 승인 트랜잭션·커넥션/잠금.
- 테스트: P5 실패 후 P2 기록 보존, 기술 재전송 집계 1회, P2 실패 접수 복구.
- 문서: 팀 합의 후 정본과 관련 명세를 함께 동기화한다. 이번에는 Markdown만 수정한다.
- 질문 6(P6 정산 구조)과 질문 8(케이스 생성 기준)은 OPEN으로 유지하며 이 결정으로 확정하지 않는다.

## 검증

미검증 — 구현·DB·트랜잭션 테스트는 수행하지 않았다. 문서 문법 검사는 [P5 안내](../payment/README.md)의 후속 수정 검증 기록을 따른다.
