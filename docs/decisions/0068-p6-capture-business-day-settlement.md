# 0068. P6 매입일 기준 영업일 D+3 정산

- 상태: P6 담당 사용자 결정, PR 리뷰 대상. 팀 운영 배포·Notion 동기화는 별도.
- 날짜: 2026-11-03
- 관련: #465, ADR-0043, docs/settlement/d3-policy-and-erd.md

## 결정

픽업 기반 72시간 계산을 매입 완료의 한국 날짜 기준 영업일 D+3로 대체한다.
픽업 API·인증·상품 스냅샷은 유지하고 주문 상세용으로만 사용한다.
달력은 P6 소유 SQL 테이블에서 읽으며, 빠진 날짜는 영업일로 추정하지 않는다.
정산의 금액·수수료는 기존 스냅샷을 유지한다. 일정은 매입과 같은 트랜잭션에서 저장한다.
완료 시 실제 지급됐다고 간주하는 기존 모의 모델은 유지하며, 기존 03:00 배치 설정을 변경하지 않는다.
환불·일정산 지급 원장·이월 차감은 정책/ERD 제안만 포함하고 후속 PR로 분리한다.

## 대안과 이유

| 대안 | 선택하지 않은 이유 |
| --- | --- |
| 픽업 +72시간 유지 | CakeShop 픽업에 종속되어 일반 가맹점 일정산 정책과 다름 |
| 매입 +72시간 | 같은 날 매입해도 시각에 따라 지급 시각이 다르고 주말·공휴일을 무시함 |
| 주말만 제외 | 법정·대체·임시 공휴일 정산일이 잘못됨 |
| 매입 중 외부 공휴일 API 호출 | 외부 장애와 응답 변경이 금융 쓰기 트랜잭션을 좌우함 |
| 오래된 Flyway 수정/DB 초기화 | 공유 DB의 이력·완료 금융 기록을 훼손함 |

## 영향

- API: 경로·DTO·HMAC·P5 이벤트 필드 유지. 픽업 LINKED의 의미는 주문 정합성 연결로 한정한다.
- DB: settlement_business_days 추가. 기존 SCHEDULED 일정만 새 정책으로 전환하며 완료/취소 행은 보존한다. 구버전 앱 쓰기 중지 후 적용한다.
- 화면: 신규 정산은 픽업 여부와 관계없이 SCHEDULED. 기존 응답의 EXPECTED 필드는 과거 호환용이며 P6 설명 문구를 매입 기준으로 바꾼다. 전체 UI 개편은 후속이다.
- 테스트: 한국 날짜 경계·동일 날짜·공휴일·주말·연도 경계·달력 누락, 미완료 전환/완료 보존, 픽업과 정산 분리·배치 경합을 확인한다.

상세 스키마·전환 실패 대응·휴일 출처·환불 후속 설계는 [P6 정책](../settlement/d3-policy-and-erd.md)을 따른다.
