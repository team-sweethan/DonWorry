## 배경과 결정

각 담당자가 업무 본문에 집중할 수 있도록 헤더·사이드바·역할별 메뉴와 공통 UI를 제공한다.
Ant Design의 폼·피드백·결과 화면을 사용하고, 테마·토큰·공통 CSS로 디자인을 맞춘다.
기존 React·Vite·Router 구성은 유지하며 React 19 호환 패치와 한국어 표시용 dayjs를 추가한다.

### 화면 폭 기준 개정 (#703)

- 1280px 이상은 기존 배치와 동작을 유지한다. 그보다 좁은 화면에서만 CSS로 반응형을 적용한다.
- 새 규칙은 `@media screen and (width < 1280px)`와 `@media screen and (width <= 760px)`에 둔다. 소수 폭에서도 빠지는 구간이 없게 범위 문법을 쓰고, A4 가로 AI 보고서 인쇄에 영향을 주지 않게 `screen`으로 한정한다.
- 태블릿에서는 저장된 사이드바 접힘 상태를 유지한다. 폰에서는 같은 메뉴를 가로 스크롤로 제공하며 저장 상태를 바꾸지 않는다.
- 사장님 홈·이용 신청 심사에 따로 있던 바깥 틀 규칙은 공통화한다. 단순한 본문은 다시 배치하고, 거래 내역·Case·보고서·정산 표의 최소 폭과 가로 스크롤은 본문 안에 둔다.
- API·DB 계약과 권한 판정은 바꾸지 않는다. 역할별 화면과 사이드바 펼침·접힘, 인쇄 비교는 프론트 검증 대상이다.

## 고려한 대안

| 대안 | 선택하지 않은 이유 |
| --- | --- |
| UI를 모두 직접 구현 | 폼·모달·알림 동작까지 중복 구현해야 함 |
| 담당자별 UI 라이브러리 선택 | 화면마다 스타일과 사용 방식이 달라짐 |
| 모바일 우선으로 CSS 전체 재작성 | 1280px 이상 기존 화면까지 바뀌어 업무 화면의 회귀 범위가 커짐 |
| 내부 직원 화면은 PC 고정 유지 | 좁은 창에서 메뉴까지 페이지 전체를 가로 스크롤해야 하고 역할별 화면 기준이 달라짐 |

## 영향

- 화면: 1280px 이상은 기존 배치를 유지하고, 그보다 좁으면 공통 틀과 업무 본문에 반응형을 적용한다. 공통 레이아웃 안에 담당 업무 페이지를 연결한다 ([현재 경로](../../frontend/README.md#화면)).
- API·DB: 계약 변경 없음. 로그인·역할 전환은 로컬 시연용이며 실제 인증·인가는 후속 연동한다.
- 의존성: Ant Design·아이콘·React 19 호환 패치·dayjs 및 잠금 파일 반영.
- 문서: 프론트 README와 적용 가이드에 실행·페이지 연결 방법을 제공한다.

## 검증

아래는 공통 레이아웃 도입 당시의 기록이다. 이후 추가된 업무 목업·API의 검증 결과를 뜻하지 않는다.

- 로컬 lint·format:check·build 통과. Fast Refresh 경고 4건과 번들 크기 경고가 남아 있다.
- Chrome에서 로그인·로그아웃·역할별 홈과 담당자 구현 영역 표시를 확인했다.
- 실제 인증·업무 API, 자동 E2E, 다른 운영체제·브라우저는 미검증이다.
