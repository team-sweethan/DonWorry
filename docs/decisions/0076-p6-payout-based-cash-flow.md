# 0076. P6 실제 지급 원장을 잔액 유입의 기준으로 사용

- 상태: 제안 — P6 정책 전환 6단계 PR 리뷰 대상
- 날짜: 2026-11-04
- 관련: #507, ADR-0068·0070·0073(P6)

## 결정

정산 조회는 원 거래 내역을 유지하고 지급 합계·환불 차감·실제 지급·미회수액을 별도로 반환한다. 실제 잔액의 유입은 merchant_payouts.payout_amount 한 번만 반영한다. 미래 유입은 남은 회수액을 예상 지급일 순서로 소진한 금액을 사용한다. 읽기 전용 스냅샷에서 계산하며 새 테이블이나 잔액 캐시는 만들지 않는다.

## 대안과 이유

- COMPLETED 건별 정산액 합산: 과거 환불 회수 차감을 놓쳐 잔액과 필요 자금을 왜곡한다.
- 과거 정산금을 감소: 기존 지급 원본을 훼손하고 이미 지급된 돈을 다시 취소한다.
- 환불 수신 즉시 현재 잔액 차감 후 향후 지급에서도 차감: 동일한 환불을 두 번 반영한다.
- 조회 기간 안에서만 채무 차감: 미래 조회가 앞선 지급의 회수를 무시하여 결과가 달라진다.
- 가변 remaining_amount를 cutoff 시점 값으로 사용: 조회 직후 회수 완료가 스냅샷에 보이면 실제 입금과 회수 기준이 어긋난다. 원 조정액에서 cutoff 이전 배분만 뺀다.
- 별도 예측 결과 테이블: 원장 변경마다 무효화가 필요하므로 원본을 읽어 계산한다.

## 영향과 한계

P6 Service·Repository·HTTP 응답 DTO·테스트·계약 문서와 프론트 수신 타입·호환 테스트를 변경한다. 화면 레이아웃·렌더링·목업은 변경하지 않는다. 모듈 api/이벤트·DB 스키마·인증·P5는 변경하지 않는다. 7단계 화면 전환과 8단계 연동/활성화는 별도다. 구체 응답·기준·한도는 [지급 기반 조회·예측 계약](../settlement/payout-forecast.md)을 따른다. 배치가 꺼져 있으면 실행 가정일 뿐 지급 약속이 아니다.
