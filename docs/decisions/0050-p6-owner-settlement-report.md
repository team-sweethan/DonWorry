# 0050. P6 사장님 정산 내역과 요약의 읽기 전용 조회

- 상태: 제안 — 사용자 구현·PR 분리 승인, 팀 리뷰 대상
- 날짜: 2026-10-30
- 관련: #228, ADR-0038 settlement → identity 공개 API 의존

## 결정

`GET /api/v1/settlements/report`에서 한국 날짜 기간별 합계·일별 값·개별 정산·상품 목록을 함께 반환한다.
인증된 사장님(OPERATOR, FINANCE_VIEW)의 가맹점만 조회한다. request body/query의 가맹점 ID는 사용하지 않는다.
동일 트랜잭션 안에서 정산 목록과 상품을 가맹점 범위로 조회하며, 조회 자체로 상태를 변경하지 않는다.
상품은 주문별 N+1 조회 대신 가맹점과 주문번호 목록으로 일괄 조회하고 원래 항목 순서를 보존한다.
날짜 미정 금액은 해당 가맹점 전체 별도 합계로 반환하고 날짜 그래프에 임의 배치하지 않는다.

## 대안

- identity Entity/Repository 직접 조회: 공개 api만 사용한다는 모듈 규칙에 어긋난다.
- 클라이언트 merchantId 수신: 다른 가맹점의 정산을 조회할 수 있는 위험이 있다.
- 합계와 상세를 각각 필수 호출: 서로 다른 시점의 합계·목록을 조합할 수 있어 초기 화면은 한 응답으로 구성한다.
- 주문별 상품 개별 조회: 주문 수에 비례하여 DB 왕복이 증가한다.
- 무제한 기간·무제한 응답: 과다 조회를 방지하기 위해 최대 366일·10,000건을 제한하고 초과 시 일부 합계를 반환하지 않는다.

## 영향

새 HTTP 계약과 P6 내부 조회 코드·테스트를 추가한다. DB·기존 migration·P1 공개 Java 계약 변경은 없다.
기존 목업·잔액·지출·현금흐름은 이번 PR에서 연결하지 않는다. 다음 배치 기준 미래 유입 예측은 후속 작업이다.
실행 설정은 기본 비활성이고 브라우저 연동은 프론트 단계에서 검증한다. 상세는 [조회 API](../settlement/report-api.md)를 따른다.
