# 0069. P6 가맹점별 일별 지급 원장

- 상태: P6 사용자 진행 승인, PR 리뷰 대상. Notion/운영 배포 합의는 별도.
- 날짜: 2026-11-03 / 관련 #474, ADR-0068

## 결정

가맹점·한국 지급일당 원장 한 건과 정산별 포함 상세를 저장한다.
가맹점별 READ_COMMITTED 트랜잭션에서 지급 행 → 정산 행을 잠그고 원장·상세·상태를 함께 확정한다.
완료 원장을 다시 열지 않으며 같은 날 늦은 대상은 다음 날로 넘긴다.
과거 완료 기록은 원본을 유지하고 LEGACY_BACKFILL 출처로 일별 원장을 구성한다.
기존 D+3 일정, 수수료 스냅샷, 실제 완료 시각, 03시 기본값·자동 실행 비활성은 유지한다.

## 고려한 대안

| 대안 | 선택하지 않은 이유 |
| --- | --- |
| 기존 건별 완료만 유지 | 가맹점 지급 합계/포함 근거가 없고 이후 환불 회수액과 연결하기 어려움 |
| 하루 원장에 실행마다 추가 | 이미 확정한 지급 금액이 바뀌고 재실행/회수 반영 기준이 모호함 |
| 모든 가맹점을 한 트랜잭션 | 한 가맹점 오류가 다른 정상 지급까지 되돌리고 잠금 범위가 커짐 |
| 기본 REPEATABLE_READ 사전 조회 후 UPSERT | 두 실제 연결에서 기존 스냅샷과 동시 생성 원장의 충돌을 재현했다. 지급 쓰기에 한해 현재 커밋 상태를 읽고 행 잠금으로 직렬화한다 |
| 상태 조회 후 잠금 없이 저장 | 동시 실행이 같은 정산을 중복 포함할 수 있음 |
| 기존 완료 기록을 삭제/다시 완료 | 금융 이력·실제 완료 시각을 훼손함 |

## 영향

- DB: P6 merchant_payouts/merchant_payout_items와 내부 FK·UNIQUE. 기존 완료 이력의 출처를 구분하는 origin 컬럼을 초안에 추가한다.
- API/의존: HTTP·P5 이벤트/공개 조회·P1 계약 변경 없음. 내부 배치 집계는 가맹점 수로 전환한다.
- 화면: 기존 정산 완료 건 합계를 유지한다. 원장 조회와 환불 차감 후 유입 표시는 후속이다.
- 검증: 동시 실행·중복·원자성·격리·이력 보존·날짜 경계·지연 대상 이월.

[ERD·전환·트랜잭션·제외 범위](../settlement/daily-payouts.md)를 따른다.
