# 0062. P6 실제 기록과 배치 기준의 일별 현금흐름 예측

- 상태: 제안 — 사용자 5단계 구현 승인, 팀 PR 리뷰 대상
- 날짜: 2026-11-02
- 관련: #230, #231, ADR-0050·0052(P6)·0053

## 결정

P6 내부의 기존 테이블을 읽어 현재 실제 기록 잔액, 일별 예상 잔액, 연속 부족 구간과 거래 근거를 반환한다.
완료 정산의 completedAt과 실제 지출의 paidAt을 사용하고, 미완료 정기 회차를 확장할 때 이미 완료한 원래 예정일은 제외한다.
미래 유입은 실제 픽업 기준 자격 시각 우선/예상 기준 보조로 배치 cron의 다음 실행에 반영한다. 기본은 한국 시간 03시다.
지난 배치 미완료·일정 미정·취소 정산은 별도 진단 금액으로 제외한다. 지난 예정일의 미완료 지출도 자동 지출/오늘 이월로 가정하지 않는다.
조회 기간 전 실제 내역은 가맹점별 DB DECIMAL 합계로 누적하고 미래 조회 시작 전 예정 거래는 계산에 이어 반영한다.
HTTP 경로·응답·한도는 [API 계약](../settlement/cash-flow-forecast-api.md)을 따른다.

가맹점·상태·완료 시각 인덱스로 누적 합계와 상세 조회의 전역 스캔을 피하며 예정 시각 인덱스로 후보·미정 조회를 지원한다.

## 대안

- 기존 현금흐름 초안 전체 병합: 이전 지출 모델·SQL·프론트 작업이 섞여 3·4단계 계약과 충돌한다.
- 예정일 경과를 실제 지출로 취급: 사용자가 기록하지 않은 출금을 만들어 현재 잔액을 왜곡한다.
- 72시간 경과 즉시 입금으로 취급: 실제 정산 완료 배치와 예측 날짜가 달라진다.
- 지난 미완료 정산을 다음 배치로 자동 이월: 지연 사유와 배치 재실행을 확인하지 않은 확정 유입을 만든다.
- 기준일부터 모든 상세를 확장하거나 366일로 제한: 장기간 사용 계정의 조회가 불가능해진다. 과거 실제 합계를 따로 조회한다.
- 예측 결과를 새 테이블에 저장: 원본 상태 변경 때 무효화가 필요하므로 이번 단계는 읽기 전용 계산을 선택한다.

## 영향과 한계

P6 HTTP 조회·내부 Repository/Service/DTO·테스트·문서를 변경한다. ADR-0059에 따라 P1 SecurityConfig에는 두 GET 경로와 동일 사장님 권한만 명시 등록하며, 관련 보안 체인 테스트를 추가한다.
새 migration으로 P6 settlements에 완료/예정 조회 인덱스 2개를 추가한다. 테이블·컬럼·데이터·모듈 의존·공개 Java API·이벤트 변경은 없다.
프론트 연결은 6단계 별도 PR이다. 배치 비활성 시에도 설정된 배치 실행을 가정하며 활성 상태를 응답에 명시한다.
실제 은행 잔액·미발생 주문 매출·시간 단위 현금 부족·메일/푸시·취소 처리 연동은 구현하지 않는다.
