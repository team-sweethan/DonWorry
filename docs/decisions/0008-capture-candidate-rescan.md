# 0008. 매입 후보의 실행별 재조회

- **상태:** PROPOSED — 사용자 선택(질문 7-A), 팀 합의 대기, 구현 없음
- **날짜:** 2026-10-20
- **관련:** [선택 기록](../payment/README.md), [미결 목록](../payment/12-open-questions.md)
- **영향 받는 담당:** P5·P6

## 배경

HELD 해제 시 최초 approved_at을 보존하므로 영구 승인시각 cursor는 해제 거래를 놓칠 수 있다.

## 결정 제안

P6는 배치마다 APPROVED를 시작점부터 재조회하고 자신의 기매입 paymentId를 제외한다. 실행 내부 페이지 cursor만 허용하고 실행 사이 승인시각 watermark를 넘기지 않는다. 매입 직전 P5 잠금과 P6 중복 방어를 병행한다.

사용자가 방향을 선택했으나 팀 채택·Notion 정본 동기화는 확인하지 않았다. 세부 계약(P6 중복 매입 제약·페이지 처리·주기·부하)은 팀 합의 대기다. 기존 ADR을 수정·대체하지 않는다.

## 고려한 대안

| 대안 | 선택하지 않은 이유·영향 |
|---|---|
| 매입 가능 시각 추가 또는 해제 이벤트만 사용 | 컬럼·이벤트 계약 확장을 피하기 위해 1차에서는 선택하지 않았다. 재조회는 후보 조회량이 늘며 실행 중 누락된 위치는 다음 실행에서 회수한다. |

## 영향

- API·DB·화면·운영: P5 매입 후보 API·P6 배치, 새 P5 컬럼 없음.
- 테스트: 오래된 HELD 해제 다음 실행 포함, 실행 중 후보 이동, 중복 배치 매입 1회.
- 문서: 팀 합의 후 정본과 관련 명세를 함께 동기화한다. 이번에는 Markdown만 수정한다.
- 질문 6(P6 정산 구조)과 질문 8(케이스 생성 기준)은 OPEN으로 유지하며 이 결정으로 확정하지 않는다.

## 검증

미검증 — 구현·DB·트랜잭션 테스트는 수행하지 않았다. 문서 문법 검사는 [P5 안내](../payment/README.md)의 후속 수정 검증 기록을 따른다.
