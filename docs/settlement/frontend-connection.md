# P6 정산·자금관리 화면 실제 API 연결 — 6단계

관련 #235, #236. 5단계 PR #407 병합 후의 HTTP 계약을 사용한다.

## 화면과 모드

- `/owner/settlements`: 서버 세션의 자기 가맹점 정산 달력·목록·수수료·상품 상세와 지출 내역.
- `/owner/funds`: 실제 완료 기록 잔액, 일별 예상 잔액·첫 부족일·최대 부족액·원인·이월 근거, 잔액/지출 관리.
- `/owner/loans`: 자금 현황에서 전달한 같은 사용자·가맹점의 예상 필요 자금만 표시한다. 직접 진입이나 다른 계정의 이전 경로 상태는 실제 근거로 사용하지 않는다. 상품 자체는 가상 예시이며 은행 조회·신청은 연결하지 않는다.
- 개발 서버의 `/dev/settlements`, `/dev/funds`는 기존 메모리 목업이다. 실제 화면의 API 실패를 목업으로 대체하지 않는다. URL 쿼리나 클라이언트 가맹점 ID로 실제 조회 대상을 바꾸지 않는다.

기존 사장님 세션·FINANCE_VIEW 경로 가드를 사용한다. HTTP는 `src/api/finance.ts`에서 공통 `api` 클라이언트로 호출하며 쿠키·CSRF·401/403 처리를 공유한다. 새 backend 경로·계산 규칙·스키마 변경은 없다.

## 계산과 표시

현금흐름 숫자와 원인은 단일 forecast 응답의 days/movements를 사용한다. 별도 정산 내역 조회를 합쳐 잔액이나 원인을 다시 계산하지 않는다.
서버의 현재 잔액·합계·최저 잔액·부족 금액과 asOf를 사용하고, 수수료·상품·빈 목록을 예시 값으로 보충하지 않는다.
정산 내역은 가능일/완료일 기준이고 현금 유입 예측은 배치 기준이므로 두 날짜가 다를 수 있음을 안내한다.
월 완료 요약은 기간 내역과 별도 조회임을 명시하며 같은 완료 범위에서 금액이 다르면 재조회를 안내한다.
한국 날짜로 기간·완료일·시각을 표시한다. 주문번호 표시와 정산 ID 키를 분리하여 같은 주문의 여러 정산도 충돌하지 않는다.

## 최초 잔액과 지출

설정 없음으로 확정되는 `404 SETTLEMENT_SETTING_REQUIRED`만 최초 입력 화면으로 처리한다. 일반 404·권한·네트워크 오류를 설정 없음으로 취급하지 않는다.
오늘 하루 시작 잔액을 한 번 저장하고 이후 수정 불가를 표시한다. 0원도 유효한 입력이다.
일회성 지출 등록·수정·삭제는 미완료 기록에만 제공하고 실제 완료 기록은 수정/삭제하지 않는다.
정기 지출은 등록·오늘부터 중단·회차별 완료를 기존 계약에 맞춘다. 완료 요청은 원래 예정일로 전송한다.
실제 완료는 실제 한국 날짜, 미완료는 원래 예정일로 표시한다. 지난 미완료는 자동 완료하지 않고 예측 제외를 표시한다.
관리 목록의 기간은 기준일 이후 최대 366일이며, 미래 예측 기간과 별개로 과거 완료/연체 예정 내역도 조회할 수 있다.
금액 입력은 서버 계약의 안전 정수 상한까지 받으며 과거 목업의 10억 원 상한은 실제 모드에 적용하지 않는다.

변경 완료 후 서버를 다시 조회한다. 저장 성공과 재조회 실패를 분리하여 저장된 요청을 무조건 재등록하도록 유도하지 않는다.
네트워크 오류로 쓰기 결과를 확인하지 못하면 자동 POST 재전송 대신 목록 재조회 후 중복 여부 확인을 안내한다.

## 취소와 재조회

기간·수정 회차·메뉴·계정이 바뀌면 이전 읽기 요청을 취소하고 늦게 도착한 응답은 게시하지 않는다.
재활성화된 조회도 새 요청으로 취급하며 로딩/오류 동안 이전 데이터를 현재 금액처럼 표시하지 않는다. 마지막 성공 조회 시각은 별도로 유지한다.
읽기 도중 로그인 버전이 바뀌면 해당 응답을 반환하지 않는다. 계정·가맹점별 화면 키와 대출 근거의 소유 범위를 분리한다.
읽기 오류는 빈 목록/0원과 구분하고 새로고침·재시도를 제공한다.

## 실행·검증 범위

Node는 package.json engines 범위(22.14 이상 또는 24 이상)를 사용한다. backend는 DB와 `settlement.owner-http.enabled=true`가 필요하다.
일반 `/login`에서 OPERATOR·FINANCE_VIEW 계정으로 로그인한다. 별도 시연 로그인·가맹점 선택 헤더를 추가하지 않는다.

검사: `npm run lint`, `npm run format:check`, `npm run build`, `npm test`.
추가 테스트는 API 경로·쿠키·CSRF·원래 회차일·중복 완료 재전달·자동 POST 재전송 없음·설정 404 구분·취소/세션 변경 후 응답 거절·한국 날짜·빈 상품/서버 수수료·계정별 대출 근거·월 요약 불일치를 검증한다.

### 미검증

브라우저 동작 검증은 수행하지 못했다. 내장 브라우저는 이 PC의 로컬 서버에 연결하지 못했고, Windows 앱 제어는 현재 브라우저 URL을 확신할 수 없다는 정책 오류로 중단됐다.
실제 backend 로그인·DB와 연결한 저장/완료/중단, 브라우저 레이아웃과 클릭·새로고침·오류 복구는 미검증이다. 합성 로컬 API 서버를 준비했으나 이를 브라우저 통과 결과로 기록하지 않는다.
운영 DB·은행 실잔액·대출 상품 API·취소 이벤트 연동은 이번 PR의 검증 범위가 아니다.

### 브라우저 확인 목록

1. 일반 로그인 후 `/owner/settlements`에서 달력/목록 전환·기간 변경·상품/수수료 상세·정산 없는 기간을 확인한다.
2. `/owner/funds`에서 최초 0원 입력과 저장 후 불변, 현재/예상 잔액·부족일·일별 원인을 확인한다.
3. 일회성·정기 등록 후 목록·예측 재조회, 미래 회차 선지출·완료 재전달·중단 후 완료 이력 보존을 확인한다.
4. 저장 성공 후 재조회 실패와 저장 결과 미확인 오류를 구분하고 무조건 재등록하지 않는지 확인한다.
5. 다음 달·기간 변경 중 늦은 응답, 새로고침 실패 시 마지막 성공 시각, 다른 계정 로그인 뒤 이전 데이터/대출 근거가 사라지는지 확인한다.
6. 개발 목업과 실제 모드 구분, 401/403/503·API 비활성·잘못된 기간에서 예시 금액으로 대체하지 않는지 확인한다.
