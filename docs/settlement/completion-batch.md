# P6 정산 완료 배치

> #465부터 픽업 완료 +72시간 조건은 매입일 기준 영업일 D+3로 대체한다. 픽업 미수신도 완료 가능하며 [현재 정책](d3-policy-and-erd.md)을 따른다.
2026-10-30 사용자 결정: 기본 실행 시간은 매일 한국 시간 03:00이다.
관련 #234. 취소 경합·취소 보류 계약은 후속 #233으로 남긴다.

## 실행과 날짜

- `settlement.completion.enabled=true`일 때만 스케줄러를 등록한다. 기본 비활성이며 이 PR은 운영 자동 실행을 켜지 않는다.
- 앱 공통 스케줄링도 활성 상태여야 한다 (`donworry.scheduling.enabled=false`이면 실행하지 않는다).
- 기본 cron은 `0 0 3 * * *`, 시간대는 `Asia/Seoul`이다. `settlement.completion.cron`으로 변경할 수 있다.
- `scheduled_at`은 매입일 기준 영업일 D+3 한국 00:00의 UTC 시각이다. `completed_at`은 건별 실제 완료 처리 시각이며 지급일로 간주한다. 실제 은행 송금은 없다.
- 서버 시작 후 앱이 준비되면 마지막으로 도래한 cron 시각까지 밀린 미완료 후보를 한 번 처리한다. 오늘의 첫 정기 실행 시각이 아직 남아 있으면 그 실행에서 함께 처리해 가맹점별 일일 지급 원장이 먼저 마감되지 않도록 한다.

## 처리 (#474 가맹점 단위 전환)

1. 실행 기준 시각과 정산 ID 상한을 고정하고 가맹점 ID를 최대 200개씩 조회한다.
2. 조회 트랜잭션을 끝낸 뒤 가맹점별 `REQUIRES_NEW` 트랜잭션을 실행한다.
3. 같은 가맹점·지급일 원장을 확보해 잠근 뒤 포함할 정산 행을 잠근다.
4. SCHEDULED 상태, 매입 완료·결제·가맹점·금액 일치, 생성·전환 시 확정해 저장한 정산일의 기준 시각 도달 여부를 재검사한다. 픽업이 없어도 대상이다.
5. 지급 원장·상세와 포함 정산 상태를 함께 저장한다. 수수료·금액·기존 정산 예정 시각은 보존한다.
6. 가맹점별 실패는 롤백하고 다음 가맹점을 계속 처리한다. 실패한 예정 건은 다음 실행의 후보가 된다. 후보 조회 자체 실패 시 이미 커밋된 완료 건은 유지된다.

수동 검증은 내부 `SettlementCompletionBatchService.run(Instant cutoff)`로 한다. 미래 기준 시각은 거절한다. 공개 실행 HTTP API는 없다.

## 제외와 검증

취소·환불·취소 진행 중 보류/해제, 현금흐름 예측 및 화면 조회는 제외한다. 취소가 연결된 환경에 활성화하기 전 #233의 계약·경합 제어를 검증해야 한다. #234 전체 완료로 간주하지 않는다.

단위 테스트는 시간 경계·반복 완료·가맹점별 실패 격리·빈 대상·미래 시각 거절을 검사한다.
격리 MariaDB 테스트는 과거 대상만 완료, 동시 실행 한 번 반영, 롤백 후 복구, 같은 주문번호의 가맹점 분리·금액 보존을 검사한다.
실제 실행 결과와 미검증은 PR에 기록한다. 개인 DB에는 테스트를 실행하지 않는다.

정산일의 달력 검증은 생성·전환 시점에 수행한다. 완료 단계에서는 달력을 다시 조회하거나 D+3를 재계산하지 않으므로, 이후 달력 변경이 기존 지급을 무기한 보류시키지 않는다.

원장 ERD·기존 완료 전환·동일일 마감/지연 대상 정책은 [2단계 지급 원장](daily-payouts.md)이 정본이다.
