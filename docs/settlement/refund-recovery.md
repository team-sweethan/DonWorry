# 5단계 지급 후 환불 회수·차감·이월 (#493)

> 정책 전환 6단계(#507)의 [실제 지급 기반 조회·예측 계약](payout-forecast.md)이 실제 유입·환불 회수 기준에 우선한다. 아래 내용은 기존 단계의 범위와 이력이다. 화면 전환은 후속이다.

## 회수 기준

P5의 기존 전액 환불 성공 이벤트 여섯 필드를 유지한다. 고객 환불은 P5의 책임이며 P6는 가맹점 순정산액의 회수만 관리한다. 수수료 전액 반환 가정으로 원 거래 금액 10,000원, 카드 수수료 200원, PG 수수료 100원이면 고객 환불액은 10,000원이고 P6 회수액은 9,700원이다. 현재 요율로 재계산하지 않는다.

- 미지급: [4단계](unpaid-refund-exclusion.md)의 CANCELED / UNPAID_EXCLUSION을 유지한다. 이미 제외한 금액을 후속 지급에서 다시 차감하지 않는다.
- 지급 완료: 원 정산 COMPLETED·완료 시각·금액과 지급 원장·상세를 보존한다. 원 지급 상세의 순정산액·가맹점·완료 상태를 대조하고 조정을 APPLIED / RECOVERY로 등록한다.
- **APPLIED / RECOVERY는 회수 대상 등록이다. 실제 회수 완료는 remaining_amount=0으로 판단한다.** 최초 잔여액은 원 순정산액이다.
- 이전 PENDING은 같은 이벤트 재전달 또는 해당 가맹점 지급 진입 시 검증·분류한다. 원 지급 근거가 없거나 불일치하면 예외로 남기고 금융 변경을 롤백한다.

## 후속 지급에서의 차감

동일 가맹점의 회수 대상 중 remaining_amount>0인 것을 **adjustment_id 오름차순**으로 처리한다. 고객 환불 시각이 과거인 이벤트가 뒤늦게 도착해도 수신 원장의 고정 순서로 재현한다.

```text
이번 차감 한도 = 이번 지급에 포함한 순정산액 합계
각 배분액 = min(남은 차감 한도, 해당 환불의 미회수액)
실제 지급액 = 순정산액 합계 - 배분액 합계
다음 미회수액 = 이전 미회수액 - 이번 배분액
```

예: 회수액 9,700원, 첫 지급 순정산액 3,880원이면 지급액 0원·잔여액 5,820원이다. 후속 순정산액 9,700원에서 5,820원을 회수하고 3,880원을 지급한다. 회수할 원금이 많아도 음수 지급을 만들지 않는다.

지급할 거래가 없으면 빈 지급 원장·배분을 만들지 않고 잔액을 유지한다. 순정산액이 0인 지급은 기존대로 완료할 수 있지만 0원 배분은 만들지 않는다. 현금 지급이 0이 된 새 정산도 이전 채무와 상계한 정산이므로 COMPLETED로 기록한다. 그 거래가 이후 환불되면 해당 원 순정산액을 다시 회수 대상으로 등록한다.

당일 완료 지급은 다시 열지 않는다. 마감 후 도착한 환불은 다음 실제 지급에서 차감한다. 새 거래가 없으면 무기한 잔여액으로 남으며 자동 출금·채무 면제·회수불가 종료 정책은 추가하지 않는다.

## ERD: payout_refund_allocations

실제 타입·제약은 [신규 SQL](../../backend/src/main/resources/db/migration/V20261103_174335__create_payout_refund_allocations.sql)이 정본이다. 기존 migration과 기존 금액 컬럼은 수정하지 않는다.

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| allocation_id | BIGINT | N | PK AUTO_INCREMENT |
| payout_id | BIGINT | N | 이번 차감이 반영된 P6 지급 원장 FK |
| adjustment_id | BIGINT | N | 원 환불 조정 원장 FK |
| applied_amount | BIGINT | N | 이번 지급에서 회수한 양수 금액 |
| created_at | DATETIME(6) | N | 배분 생성 시각, UTC |

- UNIQUE(payout_id,adjustment_id): 같은 지급에서 같은 환불을 두 번 배분하지 않는다.
- adjustment_id 인덱스로 한 환불의 전체 회수 내역을 조회한다. 지급 조회는 UNIQUE의 payout_id 선두를 사용한다.
- 양수 ID·금액 CHECK, 두 FK 모두 P6 내부이며 연쇄 삭제하지 않는다.
- 원 거래는 adjustment → settlement → 원 merchant_payout_item → 원 merchant_payout으로 추적한다. 회수는 allocation → 후속 merchant_payout으로 추적한다.
- merchant_payouts.refund_deduction_total에 이번 배분 합계를, payout_amount에 실제 차감 후 지급액을 저장한다. 기존 SQL의 합계·차감·음수 방지 제약을 그대로 사용한다.

### 별도 잔액 캐시를 만들지 않는 이유

초기 설계의 merchant_settlement_balances는 생성하지 않는다. 가맹점 잠금은 이미 4단계의 merchant_settlement_locks로 해결했고, 개별 잔액은 settlement_refund_adjustments.remaining_amount가 보유한다. 중복 합계를 저장하면 원장과 캐시를 항상 맞춰야 하며 가맹점 전체 채무가 BIGINT를 넘을 때 개별 환불까지 거절하게 된다.

회수 조정별 불변식은 `adjustment_amount = SUM(배분액) + remaining_amount`다. 미지급 제외는 회수 배분 없이 잔여액 0이다. 가맹점 합계가 필요하면 원장을 DECIMAL SUM으로 조회하고 응답 범위에서 검증한다. 한 번의 지급은 BIGINT 이내 합계만 확정하고 개별 배분은 그 한도에서 차감하므로 총 채무가 BIGINT를 넘어도 이번 회수를 처리할 수 있다.

## 트랜잭션·중복·동시 실행

[공통 가맹점 잠금](unpaid-refund-exclusion.md)을 유지한다. 잠금 행 준비는 짧게 커밋하고, 이후 하나의 READ_COMMITTED 금융 트랜잭션에서 아래 작업을 함께 처리한다.

1. 가맹점 행 잠금 → 이전 PENDING 분류.
2. 당일 지급 마감 확인 → 지급 행 → 대상 ID 조회·정산 PK 잠금.
3. 원 매입·일정·금액 검증과 순정산액 합계 계산.
4. 지급 상세, 환불 배분 원장, 개별 잔여액 감소, 정산 완료, 지급 합계·차감액·실제 지급액 확정.

금융 작업 하나라도 실패하면 위 변경을 모두 롤백한다. 최초 준비한 잠금 행만 남을 수 있다. 완료 시각은 회수 처리 뒤 다시 읽어 같은 한국 날짜에 확정하는지 확인한다. 과거 완료 원장은 갱신하지 않는다.

- 같은 환불 재전달은 기존 원장·감소한 잔여액을 유지한다.
- 같은 날 지급 재실행·동시 실행은 하나의 완료 지급과 배분만 남긴다.
- 환불 수신이 먼저 잠그면 이번 지급에서 회수할 수 있고, 지급이 먼저 확정되면 다음 지급에서 처리한다.
- 같은 가맹점의 원장 조회·잔여액 변경·지급은 같은 잠금 아래에서 수행한다. 다른 가맹점 자금으로 차감하지 않는다.
- 신규 정산 후보는 기존 cutoff/ID 상한을 유지한다. 환불은 가맹점 잠금 획득 시 커밋된 수신까지 반영한다.

## 후속과 활성화

수신·자동 배치는 기본 비활성을 유지한다. P5의 고객 환불 실행/발행 어댑터는 수정하거나 활성화하지 않는다. 은행 송금도 없다.

**조회·현금흐름·프론트는 아직 건별 COMPLETED 금액을 사용하는 부분이 있으므로 차감 후 실제 지급액 표시가 완료됐다고 보면 안 된다.** 6단계에서 실제 유입을 merchant_payouts.payout_amount로 연결하고, 7단계 화면 개편·8단계 P5/CakeShop 검증 뒤 활성화를 판단한다.

새 SQL 적용 전 구버전 금융 쓰기를 중지하고 새 코드로 전환한다. 원장·배분·금액을 수동 삭제/수정하지 않는다. 과거 데이터 일괄 보정, 운영자 복구 UI, 재시도 횟수·간격은 이번 범위가 아니다.

## 검증 계획

충분/부족/무수입/0원·여러 지급 이월, FIFO·201건 페이지, 과거 원본 보존, 지급 근거 불일치, 가맹점 격리, 총 채무 BIGINT 초과, 배분 INSERT·최종 지급 UPDATE 실패 롤백을 MariaDB에서 확인한다. 실제 두 연결의 동시 지급·차감 중 재전달과 기존 1~4단계 회귀를 실행한다. 명령·환경·미검증은 PR에 기록한다.
