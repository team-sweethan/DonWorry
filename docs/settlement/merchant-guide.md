# 사장님을 위한 결제·정산 안내

문서 버전 1.0 · 작성·검토일 2026-11-09 · 코드 기준 `7b9cc049`.

돈워리를 이용하는 **가맹점 사장님**을 위한 안내입니다. 결제 결과는 **조치 결과**, 받을 금액과 지급 내역은 **정산 내역**, 잔액과 지출 계획은 **자금 현황**에서 확인하세요. 각 메뉴는 계정에 부여된 이용 권한에 따라 표시됩니다.

이 안내는 현재 돈워리의 개발·시연 정책을 설명합니다. 카드사 처리와 지급은 모의 구현이며, 화면의 지급 완료가 실제 은행 송금을 뜻하지는 않습니다. 문서 검토일은 운영 적용일이나 가맹점 계약 발효일이 아닙니다.

## 1. 결제가 확인 중이면 어떻게 하나요?

**HELD는 결제가 승인된 뒤 확인을 위해 매입을 보류한 상태**입니다. 아직 매입이 완료되지 않았으므로 그 결제의 정산 예정금이 만들어진 상태로 보지 않습니다. 결제 확인이 언제 끝나는지, 언제 지급될지는 이 상태만으로 확정할 수 없습니다.

**조치 결과 → 해당 사건 → 결제별 결과**에서 확인하세요. 직원 판정과 실제 결제 상태는 별도로 표시됩니다.

| 보이는 내용         | 의미와 확인할 사항                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------ |
| 조사 중             | 확인이 진행 중입니다. 결제별 상태를 확인하고, 완료 시각을 임의로 예상하지 마세요.                            |
| 정상 처리 결정      | 보안 담당자의 판정입니다. 실제 결제 상태가 매입 완료인지도 확인하세요.                                       |
| 처리 진행 중        | 판정 이후 금융 처리가 아직 완료되지 않을 수 있습니다. 정상 처리 결정만으로 매입·지급 완료로 판단하지 마세요. |
| 매입 완료(CAPTURED) | 매입이 완료된 상태입니다. 정산 내역에서 해당 주문의 정산 예정일과 금액을 확인하세요.                         |
| 승인 취소(VOIDED)   | 매입 전 승인이 취소된 상태입니다. 지급 후 환불 회수와는 다른 단계입니다.                                     |
| 조사 종료           | 사건의 처리가 종료됐다는 뜻입니다. 여러 결제의 결과가 다를 수 있으므로 각 결제 상태를 보세요.                |

사장님에게는 처리 안내와 결제별 결과를 제공합니다. 내부 조사 보고서·탐지 근거·다른 고객 정보·직원 메모는 제공하지 않습니다. 상태를 조회하지 못했거나 알 수 없는 값이면 매입·취소 완료로 추정하지 말고 다시 조회하세요.

## 2. 정산 예정일은 어떻게 계산하나요?

**한국시간의 매입일을 제외하고 세 번째 영업일(D+3)**이 정산 예정일입니다. 다음 날부터 토요일·일요일·한국 공휴일을 제외하고 셉니다. 주문일·승인일·픽업일이나 단순히 72시간이 지난 시점을 기준으로 계산하지 않습니다.

| 매입일(한국시간)  | 세는 영업일                                     | 정산 예정일       |
| ----------------- | ----------------------------------------------- | ----------------- |
| 2026-11-09 월요일 | 11/10, 11/11, 11/12                             | 2026-11-12 목요일 |
| 2026-11-06 금요일 | 주말 제외 후 11/09, 11/10, 11/11                | 2026-11-11 수요일 |
| 2026-12-24 목요일 | 12/25 공휴일과 주말 제외 후 12/28, 12/29, 12/30 | 2026-12-30 수요일 |

위 날짜는 현재 돈워리 영업일 달력 기준의 예시입니다. 같은 한국 날짜에 매입됐다면 시각이 달라도 같은 정산 예정일을 사용합니다. 주말에 매입된 결제도 그다음 영업일부터 셉니다. 픽업 정보가 나중에 도착해도 정산 예정일은 픽업일로 바뀌지 않습니다.

**정산 예정일과 실제 지급 완료 시각은 다릅니다.** 지급 처리가 실행돼 완료된 내역을 확인해야 실제 지급액을 알 수 있습니다. 예정일이 표시돼도 특정 시각 입금을 보장하지 않습니다. 처리 지연이나 중지가 있으면 지급 내역과 화면의 안내를 함께 확인하세요.

## 3. 매출과 받을 금액이 왜 다른가요?

돈워리에서 금액은 다음 순서로 구분합니다.

1. **결제금액**: 매입된 원 거래 금액.
2. **순정산액**: 결제금액에서 해당 거래의 카드·PG 수수료를 뺀 금액.
3. **지급 대상 원 정산금**: 이번 지급에 포함한 순정산액의 합계.
4. **환불 회수 차감액**: 이전에 지급한 거래의 환불 때문에 이번 지급에서 회수하는 금액.
5. **실지급액**: 지급 대상 원 정산금에서 환불 회수 차감액을 뺀 금액.

현재 모의 카드 수수료는 2% 고정이고, PG 수수료는 **가맹점에 설정된 요율**을 사용합니다. 두 수수료는 거래별로 각각 계산해 원 미만을 버린 뒤 합산합니다. 기존 정산은 생성 당시의 요율과 금액을 유지하므로 이후 요율이 바뀌어도 과거 정산을 새 요율로 계산하지 않습니다.

예를 들어 **PG 수수료가 2%인 가맹점**의 600,000원 결제는 다음과 같습니다.

| 항목                                |      금액 |
| ----------------------------------- | --------: |
| 결제금액                            | 600,000원 |
| 카드 수수료(모의 2%)                | −12,000원 |
| PG 수수료(이 예시의 가맹점 요율 2%) | −12,000원 |
| 순정산액                            | 576,000원 |

576,000원은 해당 주문의 순정산액입니다. 이후 지급에서 환불 회수가 있다면 실지급액은 더 작아질 수 있습니다. PG 수수료 2%는 모든 가맹점의 공통 요율이 아닙니다. 현재 계산은 위 두 수수료를 사용하며 세금·다른 PG사의 비용 항목을 임의로 더하지 않습니다.

**정산 내역**에서 주문 상세의 원금·수수료·순정산액을 확인한 뒤 지급 내역의 원 정산금·환불 차감액·실지급액을 비교하세요. 주문별 정산금과 지급 내역을 더하면 같은 금액을 두 번 셀 수 있습니다.

## 4. 환불이 생기면 정산에 어떻게 반영되나요?

현재 지원하는 정책은 **전액 환불**입니다. 환불 성공 결과가 정산에 수신·반영된 뒤 아래 규칙을 적용합니다. 환불 접수만으로 정산 반영이 끝났다고 판단하지 마세요. 부분 환불 정책으로 확대해 해석하지 않습니다.

| 환불 시점                   | 정산 처리                                                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 아직 지급하지 않은 거래     | 해당 순정산액을 지급 대상에서 제외합니다. 이미 제외한 금액을 다음 지급에서 다시 차감하지 않습니다.                        |
| 이미 지급한 거래            | 과거 지급 내역을 보존하고, 해당 거래의 순정산액을 이후 지급에서 회수합니다.                                               |
| 다음 지급액보다 회수액이 큼 | 이번 지급액은 0원까지 줄이고 남은 회수액을 그다음 지급으로 넘깁니다. 음수 지급이나 은행 계좌 자동 출금을 만들지 않습니다. |

고객에게 돌려주는 결제금액과 가맹점에서 회수하는 순정산액은 다릅니다. 돈워리는 현재 **카드·PG 수수료를 모두 반환하는 모의 정책**을 사용합니다. 원 결제 10,000원, 카드 수수료 200원, PG 수수료 100원이었던 거래라면 고객 환불액은 10,000원이고, 정산 제외·회수 대상은 9,700원입니다. 현재 요율로 다시 계산하지 않습니다.

이미 지급한 거래에서 9,700원을 회수해야 한다면:

| 후속 지급    | 지급 대상 순정산액 | 이번 환불 차감 | 실지급액 | 남은 회수액 |
| ------------ | -----------------: | -------------: | -------: | ----------: |
| 첫 번째 지급 |            5,000원 |        5,000원 |      0원 |     4,700원 |
| 두 번째 지급 |            7,000원 |        4,700원 |  2,300원 |         0원 |

**0원 지급 기록이 있는 것과 지급 내역이 없는 것은 다릅니다.** 전자는 정산금이 환불 회수와 상계됐을 수 있고, 후자는 지급이 완료됐다는 기록이 없다는 뜻입니다. 새 지급 대상이 없으면 남은 회수액도 그대로 남습니다. 이미 마감한 지급은 다시 열지 않고 이후 지급에서 반영합니다.

화면의 **미회수액**은 조회 시점에 남아 있는 금액입니다. 과거 날짜의 정산을 보고 있어도 그 기간 말에 남아 있던 금액으로 해석하지 마세요.

## 5. 자금 현황의 예상 잔액은 무엇인가요?

**자금 현황**은 은행 계좌 조회가 아닙니다. 사장님이 입력한 시작잔액에 돈워리에서 완료 처리한 실제 지급액을 더하고, 완료 기록이 있는 지출을 빼 현재 잔액을 계산합니다. 앞으로의 잔액은 여기에 예정 정산의 환불 회수 차감 후 유입과 등록한 예정·정기 지출을 반영한 예측입니다.

- 시작잔액과 기준일을 먼저 설정하세요. 설정이 없거나 조회에 실패한 상태를 0원 잔액으로 보지 않습니다.
- 예정 유입은 설정된 지급 처리가 실행된다는 가정입니다. 화면의 기준 시각과 배치 상태·경고를 확인하세요. 지연된 미지급 금액을 이미 입금된 돈으로 합산하지 않습니다.
- 남은 환불 회수액은 미래 지급에서 차감합니다. 아직 회수하지 않은 금액을 현재 잔액에서 다시 빼거나, 지난 지급을 없애지 않습니다.
- 등록하지 않은 지출·은행 거래·아직 발생하지 않은 미래 매출은 자동으로 알 수 없습니다. 지출을 빠뜨리면 예상 잔액도 실제와 달라집니다.
- 부족 예상일은 입력과 조회 시점의 자료를 바탕으로 계산한 날짜입니다. 예측 기간에 부족이 없다는 결과가 그 이후 기간이나 하루 중 모든 시점의 잔액을 보장하지는 않습니다.

## 6. 어디서 무엇을 확인하나요?

| 확인할 것                  | 메뉴와 순서                                                           |
| -------------------------- | --------------------------------------------------------------------- |
| 확인 중 결제가 매입됐는지  | 조치 결과 → 해당 사건 → 결제별 실제 결제 상태                         |
| 주문의 정산 예정일·수수료  | 정산 내역 → 해당 날짜·주문 상세                                       |
| 지급액이 적거나 0원인 이유 | 정산 내역 → 지급 내역의 원 정산금·환불 차감액·실지급액 대조           |
| 앞으로 쓸 돈이 부족한지    | 자금 현황 → 시작잔액·지출 확인 → 조회 기간·기준 시각·부족 예상일 확인 |

이 문서는 안내의 기준 자료입니다. 문서 작성만으로 앱에 새 도움말 페이지·챗봇이 추가되는 것은 아닙니다.

## 유지보수용 근거와 적용 조건

아래는 안내를 갱신하는 개발·운영 담당자용 근거입니다. 사장님 화면에 내부 구현 정보를 그대로 노출하기 위한 내용은 아닙니다.

### 구현·활성화·검증의 구분

- 사장님에게 내부 조사 요약을 공개하지 않는 설명은 [선행 PR #692](https://github.com/team-sweethan/DonWorry/pull/692)의 변경을 기준으로 한다. 해당 변경이 반영되지 않은 버전을 이 안내와 동일한 공개 범위로 운영한다고 설명하지 않는다.
- 정산일·수수료·지급 전 제외·지급 후 회수·예측 계산은 현재 코드에 존재한다. 이번 문서는 계산·API·DB·배치 설정을 바꾸지 않는다.
- 자동 지급은 `settlement.completion.enabled=true`일 때 등록된다. 기본 cron은 한국시간 매일 03:00이지만 운영 확정 시각이나 지급 보장이 아니다. 현재 실행 환경의 활성화 여부는 이 문서로 단정하지 않는다.
- 환불의 정산 반영에는 `payment.refund-completion.enabled` 발행과 `settlement.refund-receiving.enabled` 수신 설정 및 성공 결과 전달이 필요하다. 운영 적용·재전달 확인은 [실연동 검증](integration-verification.md)을 따른다.
- 영업일 달력의 초기 범위는 2026~2027년, 자료 버전은 `KR-20261103`이다. 매입일과 D+3까지 필요한 날짜가 없으면 임의 계산하지 않고 실패한다. 2027년 말 매입은 2028년 자료가 필요할 수 있다. 임시공휴일·달력 연장은 별도 관리하며 문서 작성으로 자동 갱신되지 않는다.
- 문서 버전은 설명의 버전이며 거래별 정책 버전 필드가 추가된 것은 아니다. 운영 적용일·담당자 확인·배포 완료 여부는 해당 배포 기록에 별도로 남긴다.
- 1번 합성 시연에서 결제 84의 600,000원 → 576,000원·2026-11-12 정산 예정은 확인했다. 이번 문서의 환불·지급 예시는 계산 설명이며 새 실거래를 수행한 결과가 아니다. 근거: [시연 기록](../demo/local-demo.md).

### 외부 서비스 참고

2026-11-09 확인한 [토스페이먼츠 정산 설명](https://docs.tosspayments.com/resources/glossary/settlement)은 정산 금액·주기를 계약 조건에 따라 설명하고, 영업일 계산에서 주말·공휴일을 구분한다. [매입·수동 정산 설명](https://docs.tosspayments.com/resources/glossary/manual-settlement)은 승인·매입·정산을 별도 단계로 설명한다. 이 문서는 해당 설명 방식을 참고했다.

돈워리의 **매입일 기준 D+3, 카드 수수료 2%, 수수료 전액 반환**은 현재 프로젝트의 정책이다. 다른 PG사의 계약·요율·환불 조건이나 금융권 공통 의무라고 설명하지 않는다. 외부 자료는 개념의 참고 근거이며 돈워리의 실제 계산·적용 조건을 대체하지 않는다.
