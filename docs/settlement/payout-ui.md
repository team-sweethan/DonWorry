# P6 지급·환불 차감 기준 정산·자금 화면 — 정책 전환 7단계

관련 #512. [6단계 계약](payout-forecast.md)의 실제 지급·회수 응답을 기존 정산/자금 화면에 연결한다. DB·Flyway·백엔드·P5·인증·공용 레이아웃 변경은 없다.

## 실제 화면

- `/owner/settlements`: 서버 세션의 가맹점만 조회한다. 기간별 실제 지급액, 지급 대상 순정산금, 환불 회수 차감액, 현재 미회수액을 구분한다. 미회수액은 선택 기간 말 잔액이 아니라 현재 값임을 표시한다. 이번 달 누적도 `paidAmount`로 표시한다.
- 달력과 그래프의 초록색은 지급 원장의 `payoutAmount`다. 지급 원금 97,000원에서 전액 회수했다면 0원 지급 기록을 지우지 않는다. 파란 예정 금액은 원 정산 가능일의 **회수 차감 전** 금액이다. 실제 예상 유입은 자금 현황에서 확인한다.
- 전체 목록은 **지급 내역 / 주문별 정산 / 지출 내역**으로 나눈다. 지급 번호/주문번호/지출명을 구분해 검색하고 20건씩 확인한다. 지급 명세는 원 순정산금 − 회수액 = 실제 지급액을 보여준다.
- 주문별 `COMPLETED`는 ‘정산 완료’로 표시하며 주문 금액 자체가 개별 입금액이라는 뜻으로 사용하지 않는다. 수수료·상품·픽업 정보는 주문 상세로 유지한다. 픽업은 정산일을 계산하지 않는다.
- 과거 LEGACY_BACKFILL은 과거 이관 기록임을 구분한다. 실제로 당시 하루 한 번 지급했다는 의미로 설명하지 않는다.
- `/owner/funds`: 서버가 계산한 현재 잔액·예상 잔액·부족액을 사용한다. 원 정산금·회수액·차감 후 유입 근거, 현재 미회수액·조회 종료일까지 예상 회수·이월 잔액을 보여준다. 조회 시작 전 구간의 회수도 예상 회수 합계에 포함됨을 안내한다. 환불을 지출에서 다시 차감하지 않는다.
- 기존 최초 잔액·일회성/정기 지출·실제 지출 완료·재조회/세션 취소·대출 근거 전달을 유지한다. 대출 상품 자체는 가상이며 실거래로 연결하지 않는다.

실제 API 실패를 목업으로 대체하지 않는다. 금액은 JS 안전 정수·원장 합계·차감 식을 검증하고, 일치하지 않으면 다시 조회하도록 오류를 표시한다. 서로 다른 원 거래/지급/지출 합계를 더해 현금 유입으로 만들지 않는다.

## 목업·옆 화면

개발 서버의 `/dev/settlements`, `/dev/funds`는 API를 호출하지 않는 P6 시연 화면이다. 기존 DEV 전용 라우트만 사용하며 운영 로그인 우회나 신규 공용 경로를 추가하지 않는다.

- 시연의 오늘 지급: 원 순정산금 97,000원 − 회수 97,000원 = 실제 지급 0원.
- 현재 미회수액 150,000원을 미래 지급에 날짜 순으로 차감하고 부족하면 이월한다. 최초 잔액 입력 후 현재/예상 잔액 차이를 확인할 수 있다.
- 목업은 매입일 D를 제외하고 평일을 세 번 센다. 공휴일을 전달하면 함께 제외하며, 기본 예시는 주말만 제외한다. 완료 건은 실제 지급일과 D+3 자격일을 구분하고, 기존 EXPECTED 예시는 SCHEDULED로 덮어쓰지 않는다. 실제 공휴일·영업일 D+3 계산은 백엔드 정본을 사용한다. 카드 2%·PG 1%는 목업 예시이며 실제 화면은 저장된 수수료를 사용한다.
- 브라우저 재로드 시 목업 입력은 초기화되고 메뉴 이동 동안만 유지된다. 실제 저장은 없다.
- 공용 서버와 충돌하지 않도록 별도 Vite 포트로 실행할 수 있다: `npm run dev -- --host 127.0.0.1 --port 5180 --strictPort`.

## 같은 컴포넌트로 HTML 내보내기

`frontend/scripts/export-p6-preview.mjs`는 실제 목업 React 컴포넌트·공통 테마·Pretendard 폰트를 하나의 HTML에 번들한다. 별도 복사한 UI나 외부 CDN을 사용하지 않는다. 정산/자금/대출 목업을 HashRouter로 이동하며 실제 API나 로그인 우회 수신부는 포함하지 않는다.

`frontend`에서 `node scripts/export-p6-preview.mjs <출력 HTML 경로>`로 실행한다. 출력 경로를 생략하면 저장소의 `artifacts/DonWorry-P6-payout-preview.html`을 만든다. 생성된 큰 HTML은 소스 PR에 포함하지 않는다. 임시 폴더는 frontend 내부의 생성한 경로만 확인 후 정리한다.

## 검증과 경계

검사: `npm run lint`, `npm run format:check`, `npm test`, `npm run build`, Markdown 상대 링크 검사. 0원 지급의 그래프/달력/명세 렌더링, 지급 합계 검증, 채무 이월·기간 전 차감, 실제 잔액 이중 차감 없음, 금액 한도, 기존 날짜·지출·세션 회귀를 확인한다.

DEV 목업의 브라우저 클릭·지급 상세·자금 근거를 확인한다. 운영/실제 세션 DB 연결 및 P5/CakeShop 전액 환불 활성화는 8단계다. 내장 브라우저는 file:// 탐색을 차단하므로 생성된 독립 HTML 파일의 브라우저 클릭 검증은 미수행이며, 이 제한을 우회하지 않는다. 실제 소스의 로컬 HTTP 목업 검증과 구분한다.

## 화면 편집용 즉시 시연

개발 서버의 `/dev/funds?sample=1`은 시작 잔액 500,000원과 30일 범위로 목 그래프를 바로 연다.
`dev:sample` 메모리 저장소를 사용하며 실제 계정의 잔액·지출 API에 쓰지 않는다.
일반 `/dev/funds`의 최초 설정 동작은 유지한다. `/owner/funds`는 실제 API 조회 화면이며, 조회 실패 시 목 데이터로 자동 대체하지 않는다.

## 화면 가독성 후속 개선 검증 (2026-11-04)

- 정산·자금·대출에 P6 범위의 따뜻한 테마를 적용한다. 실제/목업이 같은 컴포넌트와 입력 형식을 사용한다.
- 금액 입력은 천 단위 쉼표와 원 단위를 표시한다. 지출명·지출 예정일·마지막 적용일과 넓은 메모 입력을 사용한다.
- 정산/잔액 그래프는 조회 기간 내 날짜 달력 선택과 가로 스크롤을 제공한다. 날짜 선택은 화면의 강조·계산 근거를 바꾸며 서버의 조회 기준 시각을 소급하지 않는다. 날짜 선택 달력의 월 이동은 조회 기간에 묶지 않는다. 기간 밖 날짜 선택 시 해당 월을 조회하며 스크롤만으로 무한 로딩하지는 않는다.
- 달력 옆에는 주문·지출 각각 최대 2건과 전체 조회 버튼을 표시한다. 지출은 공통 등록 시각이 없어 최신순을 보장하지 않으며 “최대 2건 미리보기”로 안내한다. 픽업 정보는 상세 표시만 유지하고 정산 일정 계산에는 사용하지 않는다.
- 실제 로컬 API 화면에서 지급 원장 합계 2,186,880원, 예정 정산 2,078,400원, 오늘 잔액 5,000,446,800원을 확인했다. 오늘 잔액은 최초 5,000,000,000원 + 실제 지급 916,800원 - 실제 지출 470,000원이다. 로컬 격리 DB의 가상 시연 기록이며 배포 검증이 아니다.
- 실제 테스트 DB의 환불 차감·회수 잔액은 0원이다. 환불 차감이 있는 실제 HTTP 흐름·P5/CakeShop 환불 활성화·자동 배치 실행·운영 배포 검증은 수행하지 않았다. 0원 지급·회수/이월 계산은 프론트 자동 테스트 및 기존 목업과 구분한다.
- 이번 후속 작업은 프론트엔드/P6 문서만 변경한다. DB 시드·인증 설정·Vite 로컬 프록시 설정·생성 HTML은 PR에 넣지 않는다.

## 그래프 중앙 기준선 탐색 (#522)

정산·잔액 그래프는 기준선을 화면의 같은 위치에 고정하고, 날짜를 선택하면 그래프를 이동해 해당 날짜를 맞춘다. 시작·종료 날짜도 가운데에 올 수 있도록 양끝 여백을 확보한다. 날짜 간격을 유지해 7일 조회에서도 가로 스크롤이 가능하다. 기간 밖 날짜를 선택하면 해당 월로 기간을 옮겨 다시 조회하며, 데이터가 없는 정산일에 거래를 임의로 만들지 않는다. 수동 스크롤은 보이는 구간만 이동하며 선택 날짜·계산 기준을 자동 변경하지 않는다. 날짜를 다시 선택하거나 오늘로 버튼을 누르면 해당 날짜로 재정렬한다.

정산 그래프의 달력은 이전·다음 달과 연도를 자유롭게 이동하며 기간 밖 날짜 선택 시 해당 월을 조회한다. 자금 그래프도 월 이동은 자유롭지만, 계산 가능한 날짜는 최초 잔액 기준일 이후~오늘+365일까지다(목업은 오늘을 잔액 기준일로 사용). 월 단위 조회 구간의 양끝은 이 범위에 맞춘다. 실제 API 재조회 중 화면이 다시 생성되어도 선택 날짜는 상위 화면에 보관해 유지한다.
