# P6 가맹점별 PG 수수료 계산

2026-10-30 로컬 구현. P1 공개 계약은 #357 · [ADR-0048](../decisions/0048-tenant-pg-fee-read-contract.md)을 따른다.

- 신규 정산 생성 시 `TenantReader.findById(capture.merchantId)`로 가맹점을 조회한다. identity의 Entity·Repository는 직접 참조하지 않는다.
- `TenantSummary.pgFeeRate`는 비율이다. `0.012700`은 1.27%이며 백분율 변환 없이 적용한다. 0%도 유효하다.
- 모의 카드 수수료는 2% 고정이다. 카드·PG 수수료 각각을 결제 건별로 계산하고 원 미만은 절사한다.
- 계산한 두 수수료의 합이 원금을 초과하여 정산금이 음수가 되면 저장하지 않고 예외로 중단한다.
- 정산에 적용 당시 카드·PG 수수료율, 수수료 금액과 최종 정산금을 저장한다. 이후 설정 변경이나 동일 매입 재요청으로 기존 정산을 재계산하지 않는다.
- 없는 가맹점, 조회 장애, 누락·잘못된 요율을 임시 1%로 대체하지 않는다. 예외는 매입·정산 트랜잭션으로 전파하여 함께 롤백한다.
- 가맹점 상태는 수수료 조회의 허용 여부와 구분한다. 기존 매입 요청의 정산 생성은 ACTIVE·INACTIVE 모두 저장된 요율을 사용한다.
- DB 스키마·기존 migration 변경, 기존 정산 데이터 보정, CakeShop API 계약 변경은 없다.

## 검증 항목

- `SettlementFlowTests`: 요율별 계산·절사·0%, 기존 정산 보존, 조회 누락·장애 전파, 잘못된 요율 거절.
- `SettlementFeeMariaDbTests`: 실제 P1 조회 및 MariaDB 저장, 다른 가맹점의 같은 주문번호, 설정 변경 전후 스냅샷, 가맹점 누락 시 전체 롤백.
- DB 테스트는 격리 Testcontainers에서만 실행한다. 개인 DB 시연 테스트는 명시적 환경변수가 있을 때만 실행하며, 고정 PG 1% 대신 해당 DB의 가맹점 요율을 확인한다.

테스트 작성과 실행 완료는 별개이며, 실제 실행 결과는 작업 보고를 따른다.
