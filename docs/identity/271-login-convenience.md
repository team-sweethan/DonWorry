# #271 로그인 폼 편의 기능

관련: [#271](https://github.com/team-sweethan/DonWorry/issues/271), #144 · #68 · #77.
설계 기준은 `dev 134fd0f`이며 구현은 `feature/271-login-convenience`에서 진행한다.

## 책임과 처리 순서

| 파일 | 책임 |
| --- | --- |
| `frontend/src/pages/auth/LoginPage.tsx` | 저장된 아이디·체크 상태로 폼 초기화, 제출 값 전달, Caps Lock 안내 |
| `frontend/src/auth/loginPreferences.ts` | 저장소 오류 격리, 성공한 로그인에 한해 아이디 저장·삭제 후 이동 호출 |
| `frontend/src/auth/authStore.ts` | 인증 상태에 반영한 계정 반환, 인증 상태 변경으로 무시한 응답은 `null` 반환 |
| `frontend/src/auth/AuthRoutes.tsx` | 로그인·저장 흐름 연결, 기존 목적지 결정과 이동 유지 |

1. 화면을 열 때 `donworry.auth.rememberedLoginId`를 읽는다. 값이 없거나 접근·읽기가 실패하면 빈 아이디와 체크 꺼짐을 사용한다.
2. 제출 시 아이디의 앞뒤 공백만 제거하고 비밀번호 원문·체크 여부를 고정한다. 체크 변경만으로 저장소를 수정하지 않는다.
3. 기존 로그인 API와 인증 상태 반영을 기다린다. 실패는 기존 오류 안내로 전달하고, 무시된 응답은 저장·이동하지 않는다.
4. 인증에 반영된 성공이면 체크 여부에 따라 아이디를 저장하거나 기존 값을 삭제한다. 저장소 객체 접근·쓰기·삭제 예외는 여기서만 무시한다.
5. 저장 시도 후 기존 역할·권한·복귀 경로·강제 비밀번호 변경에 따른 목적지로 이동한다. 저장소 오류가 이동을 막지 않는다.

화면 해제 여부와 관계없이 제출한 비동기 함수가 저장 처리를 끝내므로, 저장을 컴포넌트의 effect나 마운트 상태에 의존시키지 않는다.
업무 권한이 없어 403을 보는 계정과 강제 비밀번호 변경 계정도 인증 성공 시 저장 대상이다.
저장소에는 아이디 한 값만 쓰고 비밀번호·세션 정보는 쓰지 않는다. 실패 시 기존 아이디를 유지한다.

## Caps Lock과 접근성

비밀번호 입력의 `keydown`·`keyup`에서 `getModifierState('CapsLock')`을 읽고 `blur`에서 숨긴다.
포커스 재진입 후 첫 키 이벤트에서 현재 상태를 다시 확인한다.
안내 문구는 `Caps Lock이 켜져 있습니다.`이며 `role="status"`로 제공한다.
스크린 리더는 미리 있던 상태 영역의 내용 변경만 읽는 경우가 많으므로, 상태 영역은 항상 두고 문구만 바꾼다.
antd `Form.Item extra`를 사용해 비밀번호의 `aria-describedby`에 안내가 연결되도록 한다.
antd가 검증 오류의 help ID와 extra ID를 함께 구성하므로 기존 오류 연결을 덮어쓰지 않는다.

## 선택과 영향 범위

- 저장은 성공 이후만 한다. 체크 변경 즉시 저장·삭제하면 로그인 실패 시 기존 값 유지 요구와 어긋난다.
- 폼의 `onSubmit()` 정상 종료만 성공으로 간주하지 않는다. 기존 인증 저장소가 무시한 응답도 정상 종료할 수 있기 때문이다.
- 세션 저장소나 자동 로그인을 추가하지 않는다. 아이디 저장은 서버 세션의 30분 비활동 만료와 별개다.
- 별도 React 화면 테스트 도구를 도입하지 않는다. 기존 Node 러너에서 실제 사용하는 TypeScript 로직을 검사하고 화면 연결은 브라우저로 확인한다.
- 변경 범위는 P1 프론트와 테스트다. 백엔드 API·DB·모듈 간 계약·다른 담당의 업무 기능 변경은 없다.

## 검증

`frontend/tests/loginPreferences.test.ts`에서 복원·저장·삭제·실패 시 유지·저장소 오류·저장 후 이동·제출 값 고정을 검사한다.
실제 `authStore`와 연결해 로그아웃으로 무시된 응답, 인증 상태 반영 중 구독자의 로그아웃으로 무효화된 응답, 업무 권한 없는 계정과 강제 비밀번호 변경 계정도 검사한다.

실행 명령은 `cd frontend && npm run lint && npm run format:check && npm run test && npm run build`다.
체크박스·자동 채움·Caps Lock·접근성 연결·실제 이동은 브라우저 확인 대상이며, 결과와 미검증 항목은 PR에 기록한다.
