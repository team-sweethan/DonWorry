# #166 세션 만료 예고와 연장

관련: [#166](https://github.com/team-sweethan/DonWorry/issues/166), #144, #165, #125, #126,
[ADR-0014](../decisions/0014-session-authentication.md),
[ADR-0025](../decisions/0025-csrf-preparation.md).

## 동작

- 공통 API 클라이언트가 현재 인증 상태의 HTTP 응답을 활동으로 반영한다.
  익명 요청·401·네트워크 실패·로그인/로그아웃 응답·이전 인증 상태의 응답은 제외한다.
  `/me`는 본문 읽기·파싱까지 성공해야 반영하며 실패로 시간을 연장하지 않는다.
- 로그인 성공과 최초 `/me` 성공 후 추적을 시작한다. 30분 비활동 만료와 5분 전 예고는
  프론트 상수이며 백엔드 `server.servlet.session.timeout`과 함께 변경한다.
- 실제 인증 화면의 공통 모달에서 남은 시간, 연장, 로그아웃을 제공한다.
  배경·ESC로 닫히지 않는다. 연장은 기존 `/me`를 한 번 호출하며 중복 클릭을 합친다.
  연장 중에도 본문·작성 중 폼을 유지한다. 공통 API 요청과 경로 확인·정보 갱신이 진행 중이면
  기존 비활동 시한만으로 인증을 만료시키지 않는다. 공통 API는 60초 제한 시간에 실제 요청을
  취소하며, 닫힌 탭의 요청 표식도 최대 60초 후 정리해 무기한 만료 보류를 막는다.
  요청 종료 직후 공유 활동 시각·현재 시각으로 만료 여부를 다시 판단한다. 성공이면 갱신된
  시각을 따르고, 실패하면 기존 시한이 지난 경우 만료한다. 서버 401·인증 종료는 즉시 우선한다.
  기존 시한이 남아 있는 일반 오류는 안내 후 재시도한다.
- 초과 시 기존 인증 스토어의 만료 처리와 #165의 복귀 경로·이전 사용자 비교를 사용한다.
  만료 후에는 재로그인이 필요하며 자동 `/me` 복원으로 다시 진입하지 않는다.
  Router state의 `requireLogin`으로 로그인 화면 새로고침에도 이 조건을 유지한다.
  단, 다른 탭이 새로 로그인해 공유 추적이 진행 중이면 `/me`로 그 세션을 확인해 합류한다.
  그러지 않으면 탭마다 다시 로그인할 때 새 표식이 서로를 만료시켜 반복된다.
  의도적 로그아웃은 모든 탭에서 만료 안내·이전 사용자 ID·복귀 경로를 지운다.
  종료 표식을 받은 뒤 새 탭을 열어도 최초 `/me`로 되살리지 않으며, 실제 새 로그인으로
  생긴 활성 표식이 있어야 다시 확인한다. Router state 없는 진입에도 같은 규칙을 적용한다.

## 여러 탭

- `donworry.auth.activity`에는 비인증 임의 표식 `id`, 활동 시각 `at`, 종료 여부 `ended`,
  알려진 클라이언트 종료 사유 `reason`(`expired`/`logout`)을 저장한다. 이전 형식의 종료 표식은
  만료로 해석한다. 서버의 다른 기기 로그인·시간 만료 사유를 새로 추정하는 기능은 아니다.
  사용자 정보·세션 ID·토큰은 저장하지 않는다. UI 타이머를 위한 정보이며 인가 수단이 아니다.
- 로그인 성공은 새 표식을 생성하고 최초 `/me` 성공은 공유 추적에 참여한다.
  같은 탭은 즉시 알리고, 다른 탭은 `storage`·포커스·화면 복귀에서 다시 읽는다.
  만료 직전에도 공유 시각을 다시 확인한다. 다른 탭의 새 로그인·종료를 감지한 이전 화면은
  인증 정보를 지우고 로그인 화면으로 이동한다. 새 로그인이면 그 화면에서 `/me`로 다시 확인하고
  #165의 이전 사용자 비교로 복귀 경로를 정한다. 이전 탭은 새 표식의 활동을 덮어쓰지 않는다.
  로그인 화면에 있던 탭도 `storage`로 새 로그인을 감지하면 `/me`를 다시 확인한다.
  새 탭의 최초 `/me`도 활성 공유 추적에 요청 표식을 남겨 다른 탭의 만료 판정에서 보호한다.
  이 참여는 시각·추적 ID를 갱신하거나 인증을 확정하지 않는다. 종료된 추적에는 참여하지 않는다.
  이전 `/me`가 대기 중이어도 새 요청을 시작하며, 이전 요청의 늦은 성공·401·중단 결과는 버린다.
  이를 위해 다른 탭의 정상 요청까지 취소시키는 인증 변경 표식을 새로 발행하지 않는다.
- 다른 탭의 인증 변경으로 `/me` 확인이 중단되면, 공유 추적이 활성 상태일 때만 한 번 다시 확인한다.
  재시도 전과 성공 결과를 적용하기 전에 종료 사유를 다시 읽어 만료·로그아웃 표식을 되살리지 않는다.
  활동 추적 자체도 일반 확인으로 종료 표식을 교체하지 않는다.
  실제 새 로그인으로 생긴 활성 추적은 확인할 수 있다.
- 진행 요청은 요청별 `donworry.auth.request.<임의 값>`에 추적 ID·보호 종료 시각만 둔다.
  같은 추적 ID의 다른 탭도 이를 확인해 요청 응답 전에 공유 종료 표식을 쓰지 않는다.
  요청은 완료·오류·취소 후 정리하고 즉시 만료 여부를 다시 검사한다. 동시에 여러 요청이
  있으면 남은 요청도 고려한다. 오래된 세션의 요청은 새 추적을 보호하지 않는다.
- 기존 `donworry.auth.version`은 요청의 늦은 응답·CSRF 재전송 차단에 계속 사용한다.
  `refresh()`에서도 바뀌므로 이 표식을 서버 세션 ID나 활동 추적 ID로 사용하지 않는다.
- 저장소 사용이 불가능하면 현재 탭의 메모리로 계속 동작하며 탭 간 동기화는 보장하지 않는다.

## 범위와 한계

백엔드 API·DB·쿠키·단일 세션 정책은 변경하지 않는다. 새 의존성은 추가하지 않는다.
기존 Case 상세 폴링도 서버 요청이므로 활동에 포함한다. 마우스·키보드 입력만으로 연장하거나
예고 기능이 주기적으로 `/me`를 호출하는 자동 연장은 하지 않는다.

백엔드 만료 시각을 받지 않으므로 카운트다운은 추정치다. 서버의 401은 즉시 우선한다.
실제 서버 세션의 유효 여부는 서버가 결정하며 프론트 만료 처리가 서버 세션을 무효화하는 것은 아니다.
시계가 크게 변경되거나 브라우저가 실행을 중지한 동안 정확한 시점의 표시·이동은 보장할 수 없으며
다시 실행되면 현재 시각으로 계산한다.

## 검증

시간 경계·절전 복귀 계산, 두 추적기의 공유 시각 반영, 만료 직전 갱신,
이전 로그인 응답·종료 배제, 저장소 차단·잘못된 값, 공통 API의 갱신 제외,
연장 중복·오류·이전 응답 배제, 만료 후 자동 복원 방지, 만료 후 다른 탭 재로그인 합류,
인증 변경으로 중단된 `/me` 재확인, 연장 중 시한 초과 후 성공·실패·401,
대기 중인 이전 `/me` 교체와 늦은 결과 배제를 단위 테스트한다.
공통 API 클라이언트·인증 스토어·활동 추적을 함께 연결한 테스트로 일반 조회·저장·me의
지연 응답, 동시 요청, 401 우선, 취소·60초 제한 시간, 다른 탭 요청 보호, 종료 표식의 새 탭
복원, 명시적 로그아웃과 늦은 401의 경합, 저장소 차단을 검사한다.
새 탭의 최초 `/me`가 시한을 넘는 경우, 최초 확인 중 종료 표식·버전 변경의 전달 순서,
실제 새 로그인과 만료·로그아웃을 구분한 재시도, 참여 시각·ID 보존도 검사한다.
실행한 명령과 결과는 PR의 테스트 결과에 기록한다.

실제 브라우저 모달·두 탭·API 통합, 실제 30분 대기, 운영 HTTPS·프록시는
단위 테스트나 빌드 성공만으로 검증 완료라고 하지 않는다.
