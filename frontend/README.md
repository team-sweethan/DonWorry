# DonWorry 프론트엔드

React·TypeScript·Vite·Ant Design 기반 백오피스 화면입니다.
서버 세션 기반 로그인과 역할별(ADMIN·보안 직원·사장님) 메뉴를 제공합니다. Case 화면과 사장님 조치 결과는 백엔드 업무 API에 연결되어 있고, 경보 화면은 목업 데이터입니다.

## 실행

`frontend/`에서 실행합니다. 로그인은 백엔드(8081)와 DB가 필요하며 `/api` 요청은 Vite 프록시로 전달합니다.

```bash
npm ci
npm run dev
```

터미널에 표시된 주소로 접속합니다. 기본 주소는 `http://localhost:5173`입니다.
`/login`에서 Flyway 시드 계정으로 로그인합니다. ADMIN 시드 비밀번호는 저장소에 없으므로 담당자가 공유한 값을 사용합니다.

| 역할                     | 아이디       | 비밀번호 | 첫 화면          |
| ------------------------ | ------------ | -------- | ---------------- |
| 보안 직원                | `staff_test` | `1234`   | `/security/home` |
| 사장님 (DEMOSHOP 가맹점) | `boss`       | `1234`   | `/owner/actions` |
| 관리자                   | `admin`      | 담당자   | `/admin/fds`     |

보안 직원·사장님은 공개된 시연 계정입니다.
관리 화면은 최소 1280px 기준이며, 작은 창에서는 가로 스크롤을 사용합니다.

## 개발

현재 라우터에 연결된 화면은 다음과 같습니다.

| 경로                                       | 현재 상태                                                                                                           |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `/login`                                   | 실제 세션 로그인·입력 검증·오류 안내 (#78)                                                                          |
| `/`                                        | `/login`으로 이동. 로그인 상태면 역할별 첫 화면으로 이동                                                            |
| `/admin/fds`, `/admin/finance`             | ADMIN 전용 메뉴·헤더와 담당자 구현 영역 (`EmptyPage`)                                                               |
| `/demo/login`                              | 로컬 시연 로그인. 성공하면 `/dev/components`로 이동                                                                 |
| `/security/home`                           | 보안 직원 첫 화면 — Case 처리 현황·지금 처리할 사건 (#222). `/api/security-cases` 사용                              |
| `/security/cases`, `/security/cases/:id`   | Case 목록·상세·판정·인계. 백엔드 `/api/security-cases` 사용 (`src/api/cases.ts`). 시연 결제·AI 보고서만 백엔드 목업 |
| `/security/alerts`, `/security/alerts/:id` | 경보 목록·상세 목업. `src/demo/alertMockData.ts` 사용                                                               |
| `/security/transactions`                   | 거래 내역 담당자 구현 영역 (`EmptyPage`)                                                                            |
| `/owner/actions`, `/owner/actions/:id`     | 조치 결과(`FDS_VIEW`). 백엔드 `/api/merchant/security-cases` 사용 (`src/api/merchantCases.ts`, #205)                |
| `/owner/settlements`                       | 정산 현황(`FINANCE_VIEW`) 담당자 구현 영역 (`EmptyPage`)                                                            |
| `/dev/components`                          | 공통 UI 예시                                                                                                        |

Case 판정과 금융 조치 인계는 서버에 저장되고 P5로 실제 요청됩니다. "시연: HELD 결제 발생"으로 만든 시연 결제는 백엔드 목업이 처리합니다. 판정 직후에는 "금융 처리 대기 중"이고, "인계 상태 다시 확인"을 누르면 완료됩니다.

[공통 레이아웃 적용 가이드](공통레이아웃_적용가이드.md)에서 담당 페이지 연결 방법과 수정 위치를 확인합니다.
공통 UI 예시는 사이드바의 **UI 컴포넌트 보기**에서 확인할 수 있습니다.

```bash
npm run lint
npm run format:check
npm run build
npm run test
```

`npm run test`는 Node 22.6 이상에서 기본 TypeScript 실행 기능과 `node:test`를 사용합니다. 별도 테스트 라이브러리는 추가하지 않습니다.

실제 사용자 정보는 메모리에만 두고 새로고침·경로 이동 시 `/api/auth/me`로 확인합니다. 확인 중에는 보호 본문을 표시하지 않으며, 401은 비로그인/세션 만료로 처리하고 연결 실패·5xx는 관리자 화면에서 오류·재시도로 구분합니다. 로그인 화면은 보호 본문이 없으므로 경고와 함께 로그인 폼을 그대로 보여줍니다. 로그아웃은 서버 204 응답 후 완료합니다.

미로그인·만료로 `/login`에 이동하면 Router `location.state`에 원래 경로와 쿼리를 전달합니다 (#165). 로그인 후에는 `auth/loginRedirect.ts`가 내부 경로와 현재 역할·권한을 검사해 복귀 주소를 정합니다. 만료 전 계정을 알면 같은 계정일 때만 복귀하고, 최초 접근·새로고침으로 이전 계정을 모르면 현재 계정의 권한으로 판단합니다. 외부 URL·로그인 화면·해석이 달라질 수 있는 인코딩/상위 경로는 버리고 역할별 첫 화면으로 갑니다. 쿼리는 보존하지만 hash·작성 중 폼 값은 복구하지 않습니다. 의도적 로그아웃에는 복귀 정보를 남기지 않습니다.

강제 비밀번호 변경은 복귀보다 우선하며 변경 완료 후에는 기존처럼 역할별 첫 화면으로 갑니다. 업무 메뉴 권한이 없어도 본인 비밀번호 변경·로그인 이력으로는 복귀할 수 있습니다. 유효한 복귀 주소와 첫 화면이 모두 없으면 기존 403과 계정 메뉴를 보여줍니다. 이 화면 가드는 서버 인가를 대신하지 않습니다.

화면 가드는 편의 기능입니다. 서버는 `/api/auth/me`만 인증을 요구하고 다른 API 접근 제한·CSRF 활성화는 #68 5단계입니다. `/me`는 세션 정보를 반환하며 계정 상태 변경을 DB에서 다시 조회하지 않습니다.

`/admin/*`·`/security/*`·`/owner/*`는 `auth/AuthRoutes.tsx`의 `ServerSession`이 지킵니다. 역할별 메뉴와 첫 화면은 `config/navigation.ts`의 `sessionNavigation`이 정합니다. 다른 역할 화면이나 권한이 없는 사장님 메뉴는 403과 "내 홈으로"를 보여주고, 볼 수 있는 메뉴가 없는 계정은 403과 로그아웃만 보여줍니다. 권한은 로그인할 때 세션에 담으므로 권한을 바꾸면 다시 로그인해야 반영됩니다.

경보 목업은 여전히 `DemoContext`의 가맹점(기본 CakeShop)으로 데이터를 거릅니다. Case 화면은 이 값을 쓰지 않고 서버 응답을 그대로 보여줍니다(보안 직원은 모든 가맹점, 사장님은 자기 가맹점). 가맹점 선택은 시연 헤더에만 있어 서버 로그인 화면에서는 바꿀 수 없습니다.
