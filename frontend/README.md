# DonWorry 프론트엔드

React·TypeScript·Vite·Ant Design 기반 공개 랜딩과 백오피스 화면입니다.
서버 세션 기반 로그인과 역할별(ADMIN·보안 직원·사장님) 메뉴를 제공합니다. Case 화면과 사장님 조치 결과, 경보 화면은 백엔드 업무 API에 연결되어 있습니다.

## 실행

`frontend/`에서 실행합니다. 로그인은 백엔드(8081)와 DB가 필요하며 `/api` 요청은 Vite 프록시로 전달합니다.

```bash
npm ci
npm run dev
```

터미널에 표시된 주소로 접속합니다. 기본 주소는 `http://localhost:5173`입니다.
`/login`에서 Flyway 시드 계정으로 로그인합니다. ADMIN 시드 비밀번호는 저장소에 없으므로 담당자가 공유한 값을 사용합니다.

| 역할                     | 아이디       | 비밀번호 | 첫 화면          |
| ------------------------ | ------------ | -------- | ---------------- |
| 보안 직원                | `staff_test` | `1234`   | `/security/home` |
| 사장님 (DEMOSHOP 가맹점) | `boss`       | `1234`   | `/owner`         |
| 관리자                   | `admin`      | 담당자   | `/admin/home`    |

보안 직원·사장님은 공개된 시연 계정입니다.
관리 화면은 최소 1280px 기준이며, 작은 창에서는 가로 스크롤을 사용합니다.

## #315 PR 1 — 공개 랜딩

`/`는 기존 세션 확인을 거쳐 비로그인 방문자에게 서비스 소개를 보여 줍니다.
로그인된 사용자는 `sessionNavigation`의 역할·권한별 첫 화면으로 이동하며, 강제 비밀번호 변경이 우선합니다.
업무 메뉴가 없는 계정은 기존 403과 본인 계정 메뉴를 제공합니다.
연결 실패·5xx에는 공개 소개와 세션 확인 경고·다시 시도를 보여 주며, 이전 사용자 정보로 자동 이동하지 않습니다.
로그인 화면의 로고·서비스 소개 링크로 랜딩에 돌아갈 수 있습니다.
기존 업무 화면의 세션 만료 → 재로그인 → 원래 경로·쿼리 복귀와 로그아웃 후 `/login` 이동은 유지합니다.

이용 신청 버튼은 **준비 중으로 비활성화**되어 있습니다. 안내된 이용 시작 절차는 향후 흐름이며,
신청 폼·접수 API·DB·메일 발송은 후속 PR 범위입니다. 결제 연동도 별도 진행입니다.
랜딩은 업무용 1280px 최소 너비를 적용하지 않으며 좁은 화면에서 기능 카드를 한 열로 표시합니다.
본문 바로가기는 주소에 `#`을 붙이지 않고 본문으로 포커스만 옮깁니다. 해시 이동은 라우터 위치 key를 바꿔 세션 확인 화면이 잠깐 다시 뜨기 때문입니다.

### 사장님 공통 홈·업무 메뉴 (#90)

사장님은 연동 상태와 업무 권한 조합에 관계없이 `/owner` 공통 홈에서 시작합니다. 강제 비밀번호 변경과 기존의 안전한 로그인 복귀 규칙이 우선하며, 권한 있는 상세 URL로 직접 접근하면 해당 화면을 유지합니다. 로고는 공통 홈으로 이동합니다.

왼쪽 메뉴는 아래 구역을 함께 표시하고, 권한 없는 업무 메뉴와 빈 업무 구역은 숨깁니다.

| 구역      | 메뉴                               | 접근 조건      |
| --------- | ---------------------------------- | -------------- |
| 개요      | 홈                                 | 사장님         |
| 결제 보안 | 조치 결과                          | `FDS_VIEW`     |
| 자금관리  | 정산 내역·자금 현황·연계 대출 상품 | `FINANCE_VIEW` |
| 연동      | 시크릿 키 발급                     | 사장님         |

업무 권한이 없어도 홈과 시크릿 키 발급은 이용할 수 있습니다. 홈에서는 업무 권한 없음 안내를 보여줍니다. 별도 서비스 선택 화면·상단 서비스 전환·마지막 사용 서비스 저장은 추가하지 않습니다.

담당 화면은 `src/app/router.tsx`의 기존 `/owner/*` 경로에 연결합니다. 메뉴 구역·표시 권한은 `src/config/navigation.ts`, 로그인 후 이동은 `src/auth/loginRedirect.ts`, 서버 세션 화면과 로고는 `src/auth/AuthRoutes.tsx`, 사이드바 선택 표시는 `src/layouts/AdminLayout.tsx`에서 관리합니다. 상세 화면에서도 상위 업무 메뉴를 선택 상태로 표시하며 홈 메뉴는 `/owner`에서만 선택됩니다. 관리자·보안 직원의 메뉴와 역할별 경로는 유지합니다.

```bash
npm run lint
npm run format:check
npm run build
npm run test
```

`npm run test`는 Node 22.14 이상에서 기본 TypeScript 실행 기능과 `node:test`를 사용합니다. 별도 테스트 라이브러리는 추가하지 않습니다.

실제 사용자 정보는 메모리에만 두고 새로고침·경로 이동 시 `/api/auth/me`로 확인합니다. 확인 중에는 보호 본문을 표시하지 않으며, 401은 비로그인/세션 만료로 처리하고 연결 실패·5xx는 관리자 화면에서 오류·재시도로 구분합니다. 로그인 화면은 보호 본문이 없으므로 경고와 함께 로그인 폼을 그대로 보여줍니다. 로그아웃은 서버 204 응답 후 완료합니다.

미로그인·만료로 `/login`에 이동하면 Router `location.state`에 원래 경로와 쿼리를 전달합니다 (#165). 로그인 후에는 `auth/loginRedirect.ts`가 내부 경로와 현재 역할·권한을 검사해 복귀 주소를 정합니다. 만료 전 계정을 알면 같은 계정일 때만 복귀하고, 최초 접근·새로고침으로 이전 계정을 모르면 현재 계정의 권한으로 판단합니다. 외부 URL·로그인 화면·해석이 달라질 수 있는 인코딩/상위 경로는 버리고 역할별 첫 화면으로 갑니다. 쿼리는 보존하지만 hash·작성 중 폼 값은 복구하지 않습니다. 의도적 로그아웃에는 복귀 정보를 남기지 않습니다.

관리자는 로그인 시 이전 방문 주소 대신 항상 `/admin/home`에서 시작합니다 (#307). 관리자 홈은 계정·가맹점 관리 카드와 전체 건수를 상단에 크게 표시합니다. 룰 끄기 승인 대기·최근 요청·탐지 룰 현황은 아래 보조 영역에 두며, 좁은 창에서는 탐지 룰 현황이 요청 목록 아래로 이동합니다. 관리자 사이드바도 관리 메뉴를 탐지 메뉴보다 먼저 표시합니다.

강제 비밀번호 변경은 관리자 홈 이동과 복귀보다 우선하며 변경 완료 후에는 기존처럼 역할별 첫 화면으로 갑니다. 보안 직원·사장님은 업무 메뉴 권한이 없어도 본인 비밀번호 변경·로그인 이력으로는 복귀할 수 있습니다. 유효한 복귀 주소와 첫 화면이 모두 없으면 기존 403과 계정 메뉴를 보여줍니다. 이 화면 가드는 서버 인가를 대신하지 않습니다.

화면 가드는 편의 기능입니다. 서버는 `/api/auth/me`만 인증을 요구하고 다른 API 접근 제한·CSRF 활성화는 #68 5단계입니다. `/me`는 세션 정보를 반환하며 계정 상태 변경을 DB에서 다시 조회하지 않습니다.

`/admin/*`·`/security/*`·`/owner/*`는 `auth/AuthRoutes.tsx`의 `ServerSession`이 지킵니다. 역할별 메뉴와 첫 화면은 `config/navigation.ts`의 `sessionNavigation`이 정합니다. 다른 역할 화면이나 권한이 없는 사장님 메뉴는 403과 "내 홈으로"를 보여주고, 볼 수 있는 메뉴가 없는 계정은 403과 로그아웃만 보여줍니다. 권한은 로그인할 때 세션에 담으므로 권한을 바꾸면 다시 로그인해야 반영됩니다.

Case 화면은 시연 헤더의 가맹점(`DemoContext`) 값을 쓰지 않고 서버 응답을 그대로 보여줍니다(보안 직원은 모든 가맹점, 사장님은 자기 가맹점). 가맹점 선택은 시연 헤더에만 있어 서버 로그인 화면에서는 바꿀 수 없습니다.

쇼핑몰 주소의 UTS #46 검증(`tr46@7.0.0`)을 위해 Node 22.14 이상(또는 Node 24 이상)을 사용합니다. CI는 Node 22 최신 버전으로 검사합니다.
